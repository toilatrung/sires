Architecture Design · Section 2

2. Technology Stack

Trạng thái: bản 0.2 — các lựa chọn của bản 0.1 ngoài kiểu kiến trúc và ngôn ngữ backend đã được chấp thuận ngày 31/10/2026; phần tách service, NestJS và message broker là đề xuất mới, chờ xác nhận · Cơ sở: PRD 16, 17, 20.2, 21.2; ADR ở mục 12

Thay đổi so với 0.1 (chỉ đạo ngày 31/10/2026): backend tách thành nhiều service để nhiều người code song song theo ranh giới service và hợp đồng Swagger; service hệ thống viết bằng TypeScript/NestJS để build và CI nhanh, dễ bảo trì; service agent core giữ Python để có hỗ trợ provider và framework AI tốt nhất; monorepo chung cho FE và BE. Phiên bản cụ thể được ghim khi khởi tạo repo ở M1.

2.5. Dữ liệu, lưu trữ, messaging

  • PostgreSQL 16+: một cụm managed, một database và một vai trò đăng nhập riêng cho mỗi service; extension vector chỉ ở database knowledge; pg_trgm, unaccent ở service có tìm kiếm.
  • RabbitMQ (managed, cụm 3 node, quorum queue): exchange sires.events (topic) cho sự kiện; queue lệnh agent.run, knowledge.index, sandbox.build; dead-letter queue cho mỗi consumer.
  • Object storage S3-compatible, khóa theo service và tài khoản (6.6).
  • Không Redis ở MVP: phiên ở database của gateway, rate limit bằng PostgreSQL.

2.6. Xử lý tài liệu, LaTeX, sơ đồ

  • PDF: pypdfium2 + pdfplumber trong knowledge (ADR-15).
  • TeX Live cố định + latexmk, pdfLaTeX/XeLaTeX, BibTeX + natbib; @mermaid-js/mermaid-cli; rsvg-convert — trong image sandbox, điều khiển bởi sandbox-runner (NestJS).

2.7. Monorepo, CI/CD, hạ tầng, quan sát

  • Nx quản lý project graph cho cả TS và Python (Python qua target chạy lệnh uv, hoặc plugin @nxlv/python); nx affected chỉ lint, test, build service có thay đổi hoặc phụ thuộc vào thay đổi; Nx remote cache dùng chung giữa CI và máy dev.
  • Thay đổi hợp đồng trong docs/api-design kích hoạt sinh lại libs/ts/contracts và libs/py/sires_common, kéo theo mọi service dùng hợp đồng đó vào tập affected.
  • Image: một image mỗi service; base Node 22 slim cho NestJS (bundle bằng SWC, chỉ node_modules production), base Python slim cho Python.
  • Kubernetes, Terraform, Helm, GitHub Actions (giả định), OpenTelemetry — như bản 0.1 (mục 11).

2.9. Phương án đã cân nhắc

Phương ánKết luận
Modular monolith Python (bản 0.1, ADR-01/02)Thay bằng microservices NestJS + Python theo chỉ đạo 31/10/2026: CI chậm, khó chia việc song song theo ranh giới cứng.
Toàn bộ backend NestJS, kể cả agentKhông chọn: SDK và framework AI ở Python đầy đủ hơn; đội GEN AI/AIE dùng Python.
Workflow engine trong agent-core (Python)Không chọn: workflow là logic hệ thống (trạng thái, quyền, khôi phục) và liên quan nhiều service; đặt ở orchestration giúp agent-core gần như không trạng thái, scale và thay thế dễ.
Kafka, NATS JetStreamKafka nặng cho quy mô MVP; NATS JetStream nhẹ nhưng transport của NestJS chỉ hỗ trợ NATS core, phải dùng thư viện cộng đồng. RabbitMQ đủ và có hỗ trợ chính thức hai phía.
