10.2. Xác thực và phiên

  • Duy nhất eTroy OIDC (DEC-26); luồng và kiểm tra token ở F-01 và 8.8.
  • Mẫu BFF: token OIDC không bao giờ xuống trình duyệt; trình duyệt chỉ giữ cookie phiên sires_session (HttpOnly, Secure, SameSite=Lax, path /), id phiên xoay mới sau đăng nhập.
  • Hết hạn phiên: theo token eTroy; thêm hạn không hoạt động (mặc định 12 giờ) — cần PO/eTroy xác nhận (AQ-03).
  • Không có tài khoản quản trị trong ứng dụng; thao tác vận hành dữ liệu đi qua công cụ nội bộ có audit, không qua API sản phẩm.

10.3. Bảo vệ API key của người dùng

Lưu:   key (rõ) ──► DEK ngẫu nhiên (AES-256-GCM, AAD = accountId|connectionId) ──► ciphertext
       DEK ──► KMS.Encrypt(KEK "sires-provider-keys") ──► wrapped DEK
       bảng provider_secret(connection_id, ciphertext, nonce, wrapped_dek, kek_version, key_hint)
Dùng:  Model Gateway: KMS.Decrypt(wrapped DEK) → giải mã key trong bộ nhớ → gọi SDK → xóa tham chiếu
  • KEK nằm trong KMS, không rời KMS; chỉ service account của agent-core và knowledge (embedding) có quyền Decrypt; identity chỉ có quyền Encrypt (lưu key mới) và trả ciphertext qua API nội bộ chỉ cho hai service trên — identity, gateway và client không bao giờ thấy lại key (NFR-SECRETS-002).
  • “Kiểm tra kết nối” do identity gọi API nội bộ của agent-core thực hiện.
  • Xóa/thay key: xóa ciphertext ngay trong giao dịch; Agent Run bắt đầu sau đó không thể dùng key cũ (NFR-SECRETS-003). Xoay KEK định kỳ theo KMS, mã hóa lại DEK bằng job.
  • Chống lộ: bộ redaction của pino (NestJS) và structlog (Python) che chuỗi giống key (mẫu tiền tố của ba provider và chuỗi entropy cao) và mọi trường tên api_key, authorization; HTTP client của adapter tắt log header; ngoại lệ từ SDK được chuẩn hóa trước khi ghi lỗi; key không có trong context, prompt, Audit Event, export.
  • Kiểm thử NFR-SECRETS-001-AC01: chạy workflow với key mẫu đã biết, quét log, dump DB dạng rõ, object storage, Audit Event, context đã gửi.

10.4. Phân quyền và cách ly

  • Token nội bộ (ADR-20): gateway và orchestration ký JWT ngắn hạn (≤ 5 phút) bằng khóa trong KMS, mang sub (service gọi), act (actor), account_id, project_id, agent + agent_run_id và phạm vi agent (khi gọi thay agent). Mỗi service xác thực chữ ký và tự kiểm tra quyền theo token; không có endpoint nội bộ nào tin mạng nội bộ. NetworkPolicy chỉ mở các cặp service có trong hợp đồng.
  • Actor: mọi lệnh mang ActorRef — Researcher (accountId), Agent (tên + agentRunId) hoặc System (thành phần). Endpoint APR (x-apr trong API) chỉ chấp nhận actor Researcher từ phiên đăng nhập; token do agent-core dùng luôn có act = agent, nên không có đường nào để agent tạo actor Researcher; chỉ gateway (từ phiên đăng nhập) phát token actor Researcher, và orchestration chỉ chuyển tiếp token đó trong chính request trả lời prompt (F-08).
  • Permission matrix 3.5 và quyền theo trạng thái 18.2 được hiện thực trong module domain của service sở hữu (bảng tra cứu + hàm kiểm tra); test liệt kê toàn bộ ô của matrix (NFR-AUTHZ-001).
  • Phạm vi agent (3.3) hiện thực bằng context_scope của agent registry, đưa vào token nội bộ của Agent Run; API đọc của từng service kiểm tra phạm vi trước khi trả dữ liệu.
  • Cách ly: lớp ứng dụng của service + RLS trong database của service (6.3); truy cập bị từ chối trả 404 và ghi Audit Event (CTX-ISOLATION-001).
  • Global AI Assistant chạy với scope chỉ gồm Trusted Library và danh sách project (tên, trạng thái); không có tool đọc nội dung project (OQ-007).

10.5. Bảo vệ ứng dụng web

  • TLS 1.2+ ở ingress, HSTS; TLS nội bộ tới database và object storage (NFR-TRANSIT-001).
  • CSRF: token đồng bộ (synchronizer token) trả qua /auth/session, gửi ở header X-CSRF-Token cho mọi lệnh ghi; cookie SameSite=Lax là lớp thứ hai.
  • CSP chặt: default-src 'self'; không inline script; SVG sơ đồ hiển thị qua <img> (không inline) để script trong SVG không chạy; PDF qua pdf.js.
  • SSRF: base URL tùy chỉnh (agent-core, knowledge) và liên kết nguồn tải PDF (library, knowledge) đi qua HTTP client có danh sách chặn (loopback, link-local, dải private, metadata endpoint), kiểm tra sau phân giải DNS và sau mỗi redirect; chỉ agent-core, knowledge, library, gateway có egress ra Internet, qua NAT có ghi log.
  • Tải lên file: qua presigned URL có giới hạn kích thước và loại; worker kiểm tra lại nội dung; PDF chỉ được xử lý bằng thư viện trích xuất, không render bằng trình duyệt phía server.
  • Giới hạn tốc độ theo tài khoản cho endpoint ghi và tìm kiếm (token bucket trong database gateway) để chống lạm dụng.
  • Phụ thuộc: quét lỗ hổng (pip-audit, npm audit, Trivy) trong CI; image tối giản, không root.

10.6. Prompt injection và đầu ra của model

Nội dung PDF, kết quả tìm kiếm và văn bản người dùng có thể chứa chỉ dẫn độc hại nhắm vào agent. Kiến trúc giới hạn thiệt hại thay vì cố phát hiện mọi trường hợp:

  • Agent không có tool ghi và không có tool gọi mạng tùy ý; mọi ghi đi qua System sau khi Agent Run kết thúc, theo schema và quyền.
  • Mọi thay đổi có hậu quả cần phê duyệt của Researcher (APR-01–APR-10), hiển thị dạng diff/bản đề xuất.
  • Nội dung không tin cậy được đặt trong khối phân định rõ trong prompt (ví dụ thẻ <source_document>) kèm chỉ dẫn hệ thống coi đó là dữ liệu.
  • Kiểm tra tất định sau model (tham chiếu trong phạm vi, quote có thật, citation phân giải) không bị prompt vượt qua.
  • Phạm vi truy xuất do System tính, không nhận từ model (7.4).

10.7. Quyền riêng tư và dữ liệu gửi provider

  • Thông báo khi tạo Provider Connection đầu tiên, phải xác nhận đã đọc (NFR-PRIV-001); lưu thời điểm xác nhận.
  • Chỉ context do Context Assembler lắp ráp được gửi; Profile chỉ đóng góp lĩnh vực nghiên cứu khi người dùng bật (DEC-24) — kiểm tra bằng test trên context manifest.
  • Log vận hành chỉ có metadata và độ dài; accountId trong log là giá trị băm có khóa (NFR-OBS-001).
  • Debug transcript mã hóa lớp ứng dụng (DEK riêng mỗi tài khoản), chỉ chủ tài khoản xem, xóa sau 30 ngày.
  • Vùng lưu trữ dữ liệu chốt khi chọn nhà cloud (DEC-27); mọi kho dữ liệu cùng vùng.

10.8. Kiểm chứng bảo mật

  • Test tự động: endpoint không phiên (NFR-AUTH-001-AC01), vượt quyền (NFR-AUTHZ-001-AC01), chéo tài khoản (NFR-ISOL-001-AC01), chuỗi key mẫu (NFR-SECRETS-001-AC01), base URL http và địa chỉ nội bộ, sandbox đọc file/gọi mạng/vòng lặp vô hạn.
  • Review bảo mật trước M1 (auth, secrets) và trước release; kiểm thử xâm nhập độc lập trước phát hành rộng — đề xuất, cần ngân sách (AQ-04).
