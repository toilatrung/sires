12. Functional Requirements — LaTeX Manuscript Workspace

Trạng thái biên soạn: Đã duyệt — bản cuối 31/10/2026 (phiếu chốt PC-01) · Cơ sở: outline đã chốt, mục 1–6, mục 20.1

Mục này đặc tả không gian viết bản thảo LaTeX của project: khởi tạo, chỉnh sửa, AI hỗ trợ viết qua diff, bibliography gắn với Trusted Reference, compile và lịch sử revision. Luồng, quy tắc và acceptance criteria do biên soạn đề xuất (Assumption), đã được PO duyệt nội dung trong phiếu chốt PC-01 (31/10/2026). Định dạng export bản thảo: Confirmed — PO chốt 31/10/2026 (PC-01, OQ-058). Priority do biên soạn đề xuất theo tiêu chí 2.4 (OQ-011) và được PO duyệt ngày 31/10/2026 (DEC-44, bảng tổng hợp ở 2.4). MS-EDITOR-001 — Quản lý file và soạn thảo

Priority · ConfirmationP0 ·Confirmed (năng lực), Assumption (chi tiết)
PurposeResearcher sửa bản thảo trực tiếp như trong một trình soạn LaTeX thông thường.
ActorResearcher
PreconditionsProject Active; Manuscript tồn tại.
TriggerResearcher mở Manuscript, thao tác trên file tree hoặc lưu trong editor.
Main FlowFile tree: tạo, đổi tên, di chuyển, xóa file/thư mục; tải lên hình ảnh vào figures/ và file .tex có sẵn (ví dụ khi bắt đầu từ Blank với nội dung đã viết ở nơi khác). Editor: tô màu cú pháp LaTeX, gợi ý BibTeX key của Trusted Reference khi gõ lệnh citation, nhảy tới file khi chọn \input{}/\include{}. Business RulesXóa file là xóa mềm (Deleted), khôi phục được từ lịch sử. Không cho sửa tay bibliography/references.bib ở cả Default và Blank; mọi entry sinh từ Trusted Reference để giữ KPI-02 = 100% (Chốt (biên soạn 30/10/2026; PO duyệt 31/10/2026, PC-01)). Đường dẫn file không được thoát ra ngoài thư mục Manuscript.
Data & State ChangesManuscript File; Manuscript Revision (actor Researcher); Change Proposal → Outdated khi file gốc đổi.
Acceptance Criteria
  • MS-EDITOR-001-AC01 Given Researcher đổi tên sections/method.tex đang được \input, When xác nhận, Then System cảnh báo trước và sau khi đổi, compile báo đúng file thiếu nếu chưa sửa tham chiếu.
  • MS-EDITOR-001-AC02 Given Researcher lưu thay đổi, When mở lịch sử, Then có revision mới với actor Researcher.
  • MS-EDITOR-001-AC03 Given tên file chứa ../, When tạo, Then System từ chối.
DependenciesMS-REVISION-001; MS-DIFF-001; MS-BIB-001

MS-AIWRITE-001 — Writing Agent soạn và sửa section

Priority · ConfirmationP0 ·Confirmed (năng lực), Assumption (chi tiết)
PurposeTăng tốc viết mà vẫn giữ căn cứ và quyền quyết định của Researcher.
ActorWriting Agent; Researcher
PreconditionsManuscript tồn tại; có Task viết đã kích hoạt, hoặc Researcher yêu cầu trên một vùng chọn với active task (4.3).
TriggerWF-05.S5; Researcher chọn đoạn và nhập chỉ dẫn (ví dụ “viết lại ngắn gọn hơn”, “viết đoạn related work về X”).
Main FlowOrchestrator lắp ráp context (14.2): chỉ dẫn, nội dung file/vùng chọn, claim và artifact Accepted liên quan, Bibliography Entry → Writing Agent tạo Change Proposal (diff) kèm danh sách claim và citation đã dùng → CLAIM-CITATION-001 kiểm tra → Researcher xem (12.5).

Chỉ dùng BibTeX key có trong Bibliography Entry. Ngôn ngữ theo ngôn ngữ bản thảo của project. Writing Agent không sửa ngoài phạm vi file/vùng được yêu cầu.
Data & State ChangesChange Proposal Proposed; Agent Run.
Acceptance Criteria

  • MS-AIWRITE-001-AC02 Given proposal chứa citation, When kiểm tra, Then mọi key thuộc Bibliography Entry gắn Trusted Reference.
  • MS-AIWRITE-001-AC03 Given yêu cầu sửa một đoạn được chọn, When proposal tạo ra, Then diff chỉ thay đổi trong đoạn đó.

12.5. Diff and Revision Control

Confirmed (outline): hiển thị thay đổi trước khi áp dụng; cho phép chấp nhận hoặc từ chối. APR-05 (3.1).

MS-DIFF-001 — Xem và quyết định Change Proposal

Priority · ConfirmationP0 ·Confirmed (năng lực, APR-05), Assumption (chi tiết)
PurposeKhông thay đổi nào của agent vào bản thảo khi Researcher chưa xem và chấp nhận (APR-05).
ActorResearcher; System
PreconditionsChange Proposal Proposed đã qua bước phân giải citation.
TriggerChange Proposal Proposed (pending action Manuscript change proposal, 4.4).
Main FlowHiển thị diff theo file (thêm/xóa theo dòng), kết quả kiểm tra citation, danh sách claim dùng (liên kết Evidence Inspector) → Researcher chấp nhận hoặc từ chối toàn bộ proposal → khi chấp nhận: System kiểm tra revision gốc == revision hiện hành, áp dụng, tạo Manuscript Revision (nguồn: Change Proposal), proposal → Accepted.
Alternative / Error FlowsRevision đã đổi: proposal → Outdated; Researcher có thể yêu cầu Writing Agent tạo lại. Lỗi citation chặn (CLAIM-CITATION-001): nút chấp nhận vô hiệu.
Business RulesTrong MVP, Change Proposal chỉ được chấp nhận hoặc từ chối nguyên khối, không chấp nhận theo từng khối thay đổi; Change Proposal có một trạng thái duy nhất (5.8; OQ-070 đã chốt). Muốn giữ một phần, Researcher từ chối rồi yêu cầu Writing Agent tạo proposal mới hẹp hơn, hoặc sửa tay sau khi chấp nhận. Researcher có thể sửa nội dung diff trước khi chấp nhận (edit-and-approve); phần sửa ghi actor Researcher.
Data & State ChangesChange Proposal → Accepted/Rejected/Outdated; Manuscript Revision; Audit Event APR-05.
Acceptance Criteria
  • MS-DIFF-001-AC01 Given proposal tạo trên revision 5 và Researcher đã lưu revision 6, When chấp nhận proposal, Then proposal chuyển Outdated và file không đổi.
  • MS-DIFF-001-AC02 Given proposal có 3 khối thay đổi, When Researcher xem diff, Then chỉ có thao tác chấp nhận hoặc từ chối cho toàn bộ proposal, và sau khi chấp nhận revision mới chứa cả 3 khối.
  • MS-DIFF-001-AC03 Given proposal được chấp nhận, When xem Audit Event, Then có actor Researcher, APR-05 và revision tạo ra.
DependenciesMS-AIWRITE-001; MS-REVISION-001
Open Questions—

12.6. Bibliography and Citation Management

MS-BIB-001 — Bibliography gắn với Trusted Reference

Priority · ConfirmationP0 ·Confirmed (năng lực), Assumption (chi tiết)
PurposeCitation luôn đúng nguồn tin cậy (KPI-02 = 100%).
ActorSystem; Researcher
PreconditionsManuscript tồn tại; Reference Trusted.
TriggerResearcher thêm reference vào bibliography; Change Proposal dùng reference mới được chấp nhận; metadata hoặc trạng thái Reference thay đổi.
Main FlowResearcher thêm Trusted Reference vào bibliography (từ References and Evidence, từ gợi ý khi gõ citation, hoặc khi chấp nhận Change Proposal dùng reference mới) → System tạo Bibliography Entry với BibTeX key ổn định sinh từ metadata → sinh lại references.bib → khi metadata Reference được sửa, entry được cập nhật.
Alternative / Error FlowsReference bị Revoked: entry được đánh dấu; mọi citation tới nó bị kiểm tra citation báo lỗi cho đến khi Researcher thay citation hoặc duyệt lại reference (LIB-LIFECYCLE-001). Trùng key: System thêm hậu tố để key duy nhất.
Business RulesChỉ Reference Trusted có Bibliography Entry. Key không đổi sau khi tạo (để không làm vỡ citation). Không có entry “tay” không gắn Trusted Reference.
Data & State ChangesBibliography Entry; references.bib sinh lại kèm Manuscript Revision (actor System); cảnh báo trên citation.
Acceptance Criteria
  • MS-BIB-001-AC01 Given Reference Pending Approval, When thử thêm vào bibliography, Then System từ chối.
  • MS-BIB-001-AC02 Given Researcher sửa năm xuất bản trong metadata Reference, When compile lại, Then danh mục tài liệu hiển thị năm mới và key không đổi.
  • MS-BIB-001-AC03 Given Reference bị thu hồi, When mở bản thảo, Then mọi citation tới nó được đánh dấu cảnh báo.
DependenciesLIB (10.6–10.8); CLAIM-CITATION-001

MS-BUILD-001 — Compile và xem PDF

Priority · ConfirmationP0 ·Confirmed (năng lực), Assumption (chi tiết)
PurposeResearcher thấy PDF của bản thảo và hiểu lỗi build mà không cần thành thạo LaTeX.
ActorResearcher; System
PreconditionsManuscript tồn tại và có file chính trong cấu hình build.
TriggerResearcher bấm compile; sau khi chấp nhận Change Proposal (WF-05.S8, tự động — Assumption).
Main FlowSystem tạo Build Queued cho revision hiện hành → Running trong môi trường cách ly (12.8) → Succeeded: hiển thị PDF, giữ vị trí cuộn gần nhất → Failed: hiển thị danh sách lỗi đã diễn giải và log gốc.
Alternative / Error FlowsCompile mới khi build cũ đang chạy: build cũ bị hủy, chỉ build revision mới nhất. Build vượt thời gian giới hạn: Failed với lý do quá thời gian.
Business RulesMỗi lỗi hiển thị: file và dòng (nhảy tới editor), câu giải thích bằng ngôn ngữ giao diện (Tiếng Việt / English) dành cho người dùng LaTeX cơ bản, gợi ý sửa; log gốc luôn xem được. Diễn giải lỗi phổ biến (thiếu dấu ngoặc, lệnh không xác định, file hình không tìm thấy, citation không xác định) dùng quy tắc xác định; lỗi khác có thể nhờ agent giải thích, ghi rõ là gợi ý. PDF gắn với revision đã build.
Data & State ChangesBuild (log, PDF, lỗi); Audit Event.
Acceptance Criteria
  • MS-BUILD-001-AC01 Given main.tex có \includegraphics{figures/x.png} nhưng file không tồn tại, When compile, Then Build Failed và lỗi hiển thị “không tìm thấy file hình figures/x.png” kèm file, dòng và gợi ý.
  • MS-BUILD-001-AC02 Given giao diện đang ở Tiếng Việt, When có lỗi phổ biến, Then câu giải thích hiển thị bằng tiếng Việt, log gốc giữ nguyên.
  • MS-BUILD-001-AC03 Given build thành công, When xem PDF, Then PDF ghi rõ revision được build.
DependenciesMS-BUILDENV-001; INT 17.4
Open Questions—

OQ-055Engine LaTeX hỗ trợ trong MVP (pdfLaTeX, XeLaTeX, LuaLaTeX) và tập package được cài sẵn (TeX Live đầy đủ hay tối giản)?
