7. Functional Requirements — Workspace and Project

Trạng thái biên soạn: Đã duyệt — bản cuối 31/10/2026 (phiếu chốt PC-01) · Cơ sở: outline đã chốt, mục 1–6, mục 21.1

Mục này đặc tả yêu cầu chức năng cho Dashboard, vòng đời Research Project, Research Context, chat ở hai cấp và tìm kiếm. Khu vực và điều hướng theo mục 4; entity và trạng thái theo 5.1. Priority do biên soạn đề xuất theo tiêu chí 2.4 (OQ-011) và được PO duyệt ngày 31/10/2026 (DEC-44, bảng tổng hợp ở mục 20). Mọi requirement yêu cầu Researcher đã đăng nhập giả định đăng nhập qua eTroy OIDC (16, PC-01, OQ-073). Các câu hỏi của mục đã đóng, xem 7.6.

7.1. Dashboard

Confirmed (outline): project gần đây, tiến độ task, việc chờ duyệt, task đang chạy và trạng thái bản thảo.

WS-DASHBOARD-001 — Tổng quan tài khoản khi mở sản phẩm

Priority · ConfirmationP1 · Confirmed (nội dung), Assumption (luồng)
PurposeCho Researcher biết ngay việc gì đang chạy, việc gì chờ mình và nên làm gì tiếp (GOAL-02).
ActorResearcher, System
PreconditionsResearcher đã đăng nhập qua eTroy OIDC.
TriggerMở sản phẩm, hoặc chọn Dashboard.
Main Flow
  1. System tải các khối theo thứ tự ưu tiên: (1) Pending Actions, (2) Workflow đang chạy hoặc Interrupted, (3) Project gần đây, (4) tiến độ Task, (5) trạng thái bản thảo, (6) lỗi và cảnh báo gần đây.
  2. Mỗi mục có liên kết mở đúng đối tượng trong Project Workspace (4.3).
  3. Khối rỗng hiển thị trạng thái rỗng có hành động gợi ý (ví dụ “Tạo project đầu tiên”).
Alternative / Error FlowsMột khối không tải được: hiển thị lỗi tại khối đó, các khối khác vẫn hiển thị.
Business RulesChỉ hiển thị project Active trong khối project gần đây và tiến độ; project Archived không sinh pending action. Dashboard chỉ đọc; không có thao tác phê duyệt trực tiếp trên Dashboard (4.4).
Data & State ChangesKhông đổi dữ liệu. Ghi lần hoạt động cuối của tài khoản.
Acceptance Criteria
  • WS-DASHBOARD-001-AC01 Given có 2 Interactive Agent Prompt Open ở hai project, When mở Dashboard, Then khối Pending Actions hiển thị đủ 2 mục, mỗi mục ghi tên project và mở đúng prompt khi chọn.
  • WS-DASHBOARD-001-AC02 Given một Workflow ở trạng thái Interrupted, When mở Dashboard, Then workflow đó hiển thị trong khối workflow kèm hành động mở Recovery decision.
  • WS-DASHBOARD-001-AC03 Given tài khoản chưa có project, When mở Dashboard, Then hiển thị trạng thái rỗng với nút tạo project.
  • WS-DASHBOARD-001-AC04 Given một project Archived, When mở Dashboard, Then project đó không xuất hiện trong khối project gần đây.
Dependencies4.1, 4.4, PROJ-CRUD-001, TASK-PROGRESS-001, 15.1

7.2. Project CRUD

Confirmed (outline): tạo, sửa, lưu trữ và mở lại project.

PROJ-CRUD-001 — Tạo Research Project

Priority · ConfirmationP0 · Confirmed (6.1)
PurposeTạo đơn vị làm việc bền vững cho một đề tài.
ActorResearcher, System
PreconditionsResearcher đã đăng nhập qua eTroy OIDC.
TriggerChọn “Tạo project” ở Dashboard hoặc Research Projects, hoặc xác nhận đề xuất tạo project của Global AI Assistant.
Main Flow
  1. Researcher nhập tên (bắt buộc) và câu hỏi hoặc chủ đề nghiên cứu (bắt buộc); có thể nhập thêm các trường Research Context (7.3).
  2. System kiểm tra dữ liệu và tạo: Research Project Active, Research Plan rỗng, Shared Context, Research Context phiên bản 1, Audit Event.
  3. System mở Project Workspace tại Project AI Chat; Orchestrator chào và bắt đầu 6.2.
Alternative / Error Flows
  • Thiếu trường bắt buộc: không tạo; chỉ rõ trường thiếu.
  • Tạo từ Global AI Assistant: assistant điền sẵn tên và chủ đề từ hội thoại; project chỉ được tạo sau khi Researcher xác nhận form.
  • Lỗi lưu: không tạo project dở dang; báo lỗi và giữ dữ liệu đã nhập trên form.
Business RulesTên project không bắt buộc duy nhất nhưng System cảnh báo khi trùng với project Active khác. Manuscript không được tạo ở bước này (12.1). Tạo project là thao tác nguyên tử.
Data & State ChangesTạo Research Project, Research Plan, Shared Context, Research Context v1, Conversation của project, Audit Event (actor Researcher).
Acceptance Criteria
  • PROJ-CRUD-001-AC01 Given form có tên và câu hỏi nghiên cứu, When Researcher xác nhận, Then project Active được tạo và Project AI Chat mở trong ngữ cảnh project mới.
  • PROJ-CRUD-001-AC02 Given form thiếu câu hỏi nghiên cứu, When xác nhận, Then không có project nào được tạo và trường thiếu được chỉ rõ.
  • PROJ-CRUD-001-AC03 Given project vừa tạo, When Researcher đăng xuất rồi đăng nhập lại, Then project và Research Context v1 vẫn còn nguyên.
  • PROJ-CRUD-001-AC04 Given Global AI Assistant đề xuất tạo project, When Researcher chưa xác nhận form, Then không có project nào được tạo.
Dependencies5.1, 6.1, PROJ-CONTEXT-001, WS-CHAT-001
Open Questions—

PROJ-CRUD-003 — Lưu trữ, mở lại và xóa project

Priority · ConfirmationP0 · Confirmed (outline: archive, reopen); xóa mềm 30 ngày: Confirmed — PO chốt 31/10/2026 (PC-01, OQ-030)
PurposeCất project không còn làm việc mà không mất dữ liệu; mở lại khi cần; xóa project không còn dùng với thời hạn khôi phục để tránh mất dữ liệu ngoài ý muốn.
ActorResearcher, System
PreconditionsLưu trữ: project Active. Xóa: project Active hoặc Archived. Với cả hai: không có Workflow ở trạng thái Running, Waiting for User, Paused hoặc Interrupted. Mở lại: project Archived. Khôi phục: project đã xóa mềm chưa quá 30 ngày.
TriggerResearcher chọn “Lưu trữ”, “Mở lại”, “Xóa” hoặc “Khôi phục”.
Main Flow
  1. Lưu trữ: System kiểm tra điều kiện → Researcher xác nhận (APR-08) → project Archived; pending action của project chuyển Expired với lý do “project đã lưu trữ”.
  2. Mở lại: Researcher chọn → project Active; System tính lại trạng thái Task theo baseline hiện hành.
  3. Xóa: System kiểm tra điều kiện → hiển thị cảnh báo nêu dữ liệu sẽ bị xóa (Plan, Task, evidence, artifact, bản thảo, lịch sử chat) và hạn khôi phục 30 ngày → Researcher xác nhận (APR-08) → System xóa mềm: ghi deletedAt, ẩn project khỏi mọi khu vực, tìm kiếm và context của agent; pending action của project chuyển Expired với lý do “project đã xóa”.
  4. Khôi phục: trong 30 ngày kể từ khi xóa, Researcher mở danh sách project đã xóa ở Research Projects và chọn khôi phục → project trở lại trạng thái trước khi xóa (Active hoặc Archived) với đầy đủ dữ liệu.
  5. Hết 30 ngày: System xóa vĩnh viễn toàn bộ dữ liệu cấp project theo NFR-RET-002; Trusted Reference không bị ảnh hưởng.
Alternative / Error Flows
  • Còn workflow hoạt động: không cho lưu trữ hoặc xóa; liệt kê workflow và cho phép hủy từng cái (ORCH-FAILURE-001).
  • Researcher hủy hộp thoại xác nhận xóa: không thay đổi gì.
  • Khôi phục sau 30 ngày: không còn trong danh sách project đã xóa; không khôi phục được.
Business RulesProject Archived chỉ đọc (5.1). Lưu trữ và xóa không ảnh hưởng Trusted Reference (OWN-04). Project đã xóa mềm không sửa được, không chạy được Task và không xuất hiện ở Dashboard hay Global AI Assistant; chỉ thấy ở danh sách project đã xóa kèm ngày xóa vĩnh viễn dự kiến. Xóa vĩnh viễn chỉ do System thực hiện khi hết hạn; không có thao tác xóa vĩnh viễn ngay trong MVP. Agent không được xóa project (3.4). Chính sách theo NFR-RET-002 và 16.8 (PC-01, OQ-030, OQ-078).
Data & State ChangesResearch Project.status; Research Project.deletedAt (18); Pending Action → Expired; Audit Event cấp tài khoản cho xóa và khôi phục (actor Researcher); xóa vĩnh viễn dữ liệu cấp project khi hết hạn.
Acceptance Criteria
  • PROJ-CRUD-003-AC01 Given project có một Workflow Running, When Researcher chọn lưu trữ, Then thao tác bị chặn và workflow được liệt kê.
  • PROJ-CRUD-003-AC02 Given project Archived, When Researcher cố kích hoạt một Task, Then hệ thống từ chối và không tạo Workflow.
  • PROJ-CRUD-003-AC03 Given project Archived dùng reference R, When mở Trusted Library, Then R vẫn Trusted và dùng được ở project khác.
  • PROJ-CRUD-003-AC04 Given project vừa mở lại, When mở Plan and Tasks, Then trạng thái Task khớp với baseline và dependency hiện hành.
  • PROJ-CRUD-003-AC05 Given project Active không có workflow hoạt động, When Researcher xác nhận xóa, Then project biến khỏi Dashboard, Research Projects, tìm kiếm và Global AI Assistant, và xuất hiện trong danh sách project đã xóa kèm ngày xóa vĩnh viễn dự kiến.
  • PROJ-CRUD-003-AC06 Given project đã xóa mềm 10 ngày trước, When Researcher chọn khôi phục, Then project trở lại trạng thái trước khi xóa với đầy đủ Plan, Task, artifact và bản thảo.
  • PROJ-CRUD-003-AC07 Given project đã xóa mềm quá 30 ngày, When System chạy tác vụ dọn dữ liệu, Then toàn bộ dữ liệu cấp project bị xóa vĩnh viễn, project không còn khôi phục được, và Trusted Reference từng dùng trong project vẫn Trusted.
  • PROJ-CRUD-003-AC08 Given project có một Workflow Waiting for User, When Researcher chọn xóa, Then thao tác bị chặn và workflow được liệt kê.
Dependencies5.0, 5.1, OWN-04, ORCH-FAILURE-001, TASK-STATE-001, NFR-RET-002, 16.8
Open QuestionsOQ-030 (đã đóng 31/10/2026, PC-01)

7.3. Research Context

Confirmed (outline): câu hỏi nghiên cứu, lĩnh vực, từ khóa, ràng buộc, mục tiêu và citation preferences.

PROJ-CONTEXT-001 — Nhập và sửa Research Context có phiên bản

Priority · ConfirmationP0 · Confirmed (trường), Assumption (phiên bản)
PurposeLưu ngữ cảnh nghiên cứu có cấu trúc làm nền cho Plan và mọi Agent Run.
ActorResearcher, System
PreconditionsProject Active.
TriggerResearcher sửa Research Context ở Overview, hoặc xác nhận đề xuất của Orchestrator (PROJ-CONTEXT-002).
Main Flow
  1. Form gồm: câu hỏi nghiên cứu (bắt buộc), mục tiêu, lĩnh vực, từ khóa, phạm vi, ràng buộc (thời gian, phương pháp, nguồn), loại sản phẩm đầu ra, ngôn ngữ bản thảo (mặc định English — DEC-14), citation style ưa thích.
  2. System lưu thành phiên bản Research Context mới; phiên bản cũ giữ nguyên.
  3. Nếu có baseline Approved, System hiển thị cảnh báo: thay đổi mục tiêu, câu hỏi, phạm vi hoặc phương pháp có thể là thay đổi lớn và gợi ý xem lại Plan (PLAN-IMPACT-001).
Alternative / Error FlowsXóa trống câu hỏi nghiên cứu: không cho lưu.
Business RulesMỗi Plan Version ghi phiên bản Research Context nó dựa vào (5.1). Citation style chỉ là ưu tiên cho bản thảo; không đổi Trusted Reference.
Data & State ChangesResearch Context version mới; Context Item không đổi; Audit Event.
Acceptance Criteria
  • PROJ-CONTEXT-001-AC01 Given Research Context phiên bản 2, When Researcher đổi từ khóa và lưu, Then phiên bản 3 được tạo và phiên bản 2 vẫn xem được.
  • PROJ-CONTEXT-001-AC02 Given có baseline Approved, When Researcher đổi câu hỏi nghiên cứu, Then hệ thống hiển thị cảnh báo ảnh hưởng tới Plan.
  • PROJ-CONTEXT-001-AC03 Given Plan Version v2 tạo khi Research Context ở phiên bản 3, When xem v2, Then thấy tham chiếu tới Research Context phiên bản 3.
Dependencies5.1, 5.2, PLAN-IMPACT-001
Open Questions—

7.4. Global and Project Chat

WS-CHAT-001 — Global AI Assistant

Priority · ConfirmationP1 · Confirmed (SCOPE-02; phạm vi chốt ở OQ-007)
PurposeHỗ trợ ở cấp tài khoản: điều hướng, tạo project, tra cứu Trusted Library.
ActorResearcher, Orchestrator (phiên global)
PreconditionsOrchestrator có Agent Model Assignment với Provider Connection Valid.
TriggerResearcher gửi tin nhắn ở Global AI Assistant.
Main FlowOrchestrator nhận tin nhắn cùng context global (danh sách project: tên, trạng thái; metadata Trusted Library) → trả lời, gợi ý điều hướng (liên kết tới khu vực), đề xuất tạo project (PROJ-CRUD-001) hoặc trả về reference phù hợp trong Trusted Library.
Alternative / Error Flows
  • Yêu cầu cần dữ liệu trong project (ví dụ “tóm tắt evidence của project X”): assistant giải thích giới hạn và đưa liên kết mở Project AI Chat của project đó.
  • Chưa cấu hình provider: hiển thị thông báo và liên kết tới Settings › Agent Models.
Business RulesKhông thực thi Task, không tạo Plan, không đọc nội dung project (SCOPE-02, 4.3). Lịch sử Global Conversation lưu bền vững.
Data & State ChangesConversation/Message cấp tài khoản; Agent Run của Orchestrator.
Acceptance Criteria
  • WS-CHAT-001-AC01 Given hai project có evidence, When Researcher hỏi Global AI Assistant về nội dung evidence, Then context gửi cho model không chứa evidence của project nào và câu trả lời dẫn tới Project AI Chat.
  • WS-CHAT-001-AC02 Given Trusted Library có reference chứa từ khóa K, When Researcher hỏi tài liệu về K, Then câu trả lời liệt kê reference đó kèm liên kết.
  • WS-CHAT-001-AC03 Given Researcher quay lại sau khi đăng xuất, When mở Global AI Assistant, Then lịch sử hội thoại trước đó còn nguyên.
Dependencies4.1, ORCH-INTENT-001, CTX-ISOLATION-001 (14.5)
Open QuestionsOQ-007 (đã giải quyết)

PROJ-CHAT-001 — Project AI Chat với lịch sử và ngữ cảnh rõ ràng

Priority · ConfirmationP0 · Confirmed (outline)
PurposeKênh làm việc chính với Orchestrator trong một project.
ActorResearcher, Orchestrator, System
PreconditionsProject Active (project Archived: chỉ đọc lịch sử).
TriggerResearcher gửi tin nhắn trong Project AI Chat.
Main Flow
  1. System lưu Message với projectId và active task (nếu có).
  2. Orchestrator nhận context do System lắp ráp từ Shared Context (14.2), không chỉ từ lịch sử chat.
  3. Orchestrator trả lời, tạo prompt, hoặc khởi động workflow được phép (ORCH-INTENT-001).
  4. Interactive Agent Prompt hiển thị nhúng trong luồng chat và trả lời được tại chỗ (15.3).
Alternative / Error FlowsProvider lỗi: tin nhắn của Researcher vẫn được lưu; hiển thị lỗi kèm nút thử lại (ORCH-FAILURE-001).
Business RulesLịch sử chat không phải nguồn sự thật duy nhất: quyết định quan trọng phải được ghi thành Context Item hoặc phê duyệt có cấu trúc (3.2). Context gửi model chỉ gồm dữ liệu của project này (3.4).
Data & State ChangesMessage; Agent Run; có thể sinh Context Item summary định kỳ.
Acceptance Criteria
  • PROJ-CHAT-001-AC01 Given hai project A và B, When Researcher chat trong A, Then context gửi Orchestrator không chứa Message, Context Item hay evidence của B.
  • PROJ-CHAT-001-AC02 Given một quyết định đã trả lời qua prompt ở phiên trước, When Researcher mở phiên chat mới, Then Orchestrator nhận quyết định đó qua Shared Context.
  • PROJ-CHAT-001-AC03 Given provider trả lỗi, When Researcher gửi tin nhắn, Then tin nhắn được lưu và có nút thử lại.
Dependencies5.5, 5.11, 14.2, PROMPT-LIFECYCLE-001
Open Questions—

PROJ-CHAT-002 — Active task context
