Priority · ConfirmationP0 · Confirmed (thành phần), Assumption (kiểm tra)
PurposePlan đề xuất đủ cấu trúc để duyệt và thực thi mà không phải đoán.
ActorOrchestrator, System
PreconditionsWF-01.S1–S3 đã xong.

Main Flow

9.2. Plan Review and Approval

Confirmed (outline, 20.1): sửa, so sánh, duyệt, từ chối và quản lý phiên bản Plan; Plan được duyệt trước khi thực thi chính thức.

PLAN-REVIEW-001 — Sửa và so sánh Plan Version

Priority · ConfirmationP0 · Confirmed (outline)
PurposeResearcher kiểm soát nội dung Plan trước khi duyệt.
ActorResearcher, Orchestrator, System
PreconditionsCó Plan Version Draft.
TriggerResearcher mở Plan and Tasks hoặc yêu cầu Orchestrator sửa Plan.
Main Flow
  1. Researcher sửa trực tiếp: thêm/xóa/sửa Task, Phase, dependency, label; kéo thả thứ tự.
  2. Hoặc yêu cầu Orchestrator sửa: Orchestrator tạo đề xuất thay đổi hiển thị dạng so sánh; Researcher áp dụng từng phần hoặc toàn bộ.
  3. So sánh: hiển thị khác biệt giữa Draft và baseline (hoặc hai version bất kỳ): Task thêm/xóa/sửa, dependency, label, goals, methods; đánh dấu thay đổi lớn theo MC-01–MC-08 (9.11).
  4. Researcher trình duyệt → Proposed.
Alternative / Error FlowsMuốn sửa version Proposed: Researcher rút lại → System tạo Draft mới sao chép nội dung và chuyển bản Proposed sang Rejected với lý do “rút lại để sửa” (5.2, 18.2).
Business RulesTối đa một Draft hoặc Proposed mở (5.2). Version Approved, Superseded, Rejected chỉ đọc.
Data & State ChangesPlan Version (nội dung, trạng thái); Audit Event.
Acceptance Criteria
  • PLAN-REVIEW-001-AC01 Given baseline v1 và Draft v2 thêm một Task và đổi một dependency, When so sánh, Then hiển thị đúng hai thay đổi và cả hai được đánh dấu thay đổi lớn.
  • PLAN-REVIEW-001-AC02 Given Orchestrator đề xuất sửa Draft, When Researcher chưa áp dụng, Then nội dung Draft không đổi.
  • PLAN-REVIEW-001-AC03 Given đã có Draft mở, When Orchestrator cố tạo Draft thứ hai, Then System từ chối.
Dependencies5.2, PLAN-IMPACT-001
Open Questions—

PLAN-APPROVAL-001 — Duyệt hoặc từ chối Plan Version

Priority · ConfirmationP0 · Confirmed (20.1, APR-01)
PurposeTạo baseline chính thức cho thực thi.
ActorResearcher, System
PreconditionsPlan Version Proposed qua kiểm tra cấu trúc.
TriggerResearcher chọn duyệt hoặc từ chối (trực tiếp hoặc qua prompt APR-01).
Main Flow
  1. Duyệt: version → Approved; baseline cũ → Superseded; Research Plan.baselineVersionId cập nhật; Audit Event (APR-01).
  2. System áp dụng baseline mới cho Task: Task mới → tính theo T-01/T-02; Task bị loại → Cancelled (T-18) nếu không có workflow hoạt động; Task đổi định nghĩa → áp dụng PLAN-IMPACT-001.
  3. Từ chối: version → Rejected kèm lý do bắt buộc; baseline không đổi.
Alternative / Error FlowsTask bị loại khỏi baseline đang có workflow hoạt động: Task giữ trạng thái, gắn cờ “không còn trong baseline”; Researcher quyết định hủy workflow hoặc để chạy xong rồi hủy Task.
Business RulesChỉ Researcher duyệt. Không Task nào được Queued khi chưa có baseline. Thay đổi không thuộc danh sách thay đổi lớn (MC-01–MC-08, 9.11) được duyệt nhanh trong một thao tác; System vẫn tạo Plan Version mới và ghi phê duyệt APR-01 (Confirmed — PO chốt 31/10/2026, PC-01, OQ-026). Plan Version có ít nhất một thay đổi lớn không được duyệt nhanh.
Data & State ChangesPlan Version; Research Plan; Task; Audit Event.
Acceptance Criteria
  • PLAN-APPROVAL-001-AC01 Given baseline v1 và v2 Proposed, When Researcher duyệt v2, Then v2 Approved, v1 Superseded, và chỉ có một version Approved.
  • PLAN-APPROVAL-001-AC02 Given v2 loại Task T3 đang In Progress, When duyệt v2, Then T3 không bị hủy tự động và hiển thị cờ “không còn trong baseline”.
  • PLAN-APPROVAL-001-AC03 Given Researcher từ chối mà không nhập lý do, When xác nhận, Then thao tác bị chặn.
  • PLAN-APPROVAL-001-AC04 Given project chưa có baseline, When Researcher cố kích hoạt Task, Then hệ thống từ chối với lý do “Plan chưa được duyệt”.
  • PLAN-APPROVAL-001-AC05 Given Draft v3 chỉ sửa chính tả mô tả một Task so với baseline v2, When Researcher chọn duyệt nhanh, Then một thao tác đưa v3 thành Approved, v2 thành Superseded, và Audit Event ghi APR-01 cho v3.
  • PLAN-APPROVAL-001-AC06 Given Draft v3 có một thay đổi lớn (ví dụ MC-05), When Researcher mở màn hình duyệt, Then không có thao tác duyệt nhanh; v3 phải qua trình duyệt Proposed và APR-01 đầy đủ.
DependenciesWF-01.S7, PROMPT-APPROVAL-001, TASK-STATE-001
Open QuestionsOQ-026 (đã đóng 31/10/2026, PC-01)

9.4. Task Dependency Graph

Confirmed (outline): biểu diễn quan hệ tiên quyết và phát hiện chu trình.

TASK-DEPENDENCY-001 — Dependency graph không chu trình

Priority · ConfirmationP0 · Confirmed (outline)
PurposeXác định Task nào phải xong trước Task nào.
ActorResearcher, Orchestrator, System
PreconditionsPlan Version Draft.
TriggerThêm, sửa, xóa dependency.
Main FlowDependency là quan hệ “Task B cần Task A Completed”, có thể kèm “dùng đầu ra X của A làm đầu vào”. System kiểm tra ngay khi thêm: nếu tạo chu trình, từ chối và chỉ ra chuỗi Task tạo chu trình.
Alternative / Error FlowsXóa Task có Task khác phụ thuộc: System liệt kê Task phụ thuộc và yêu cầu Researcher chọn bỏ dependency hoặc thay Task tiên quyết.
Business RulesDependency chỉ giữa Task trong cùng Plan Version. Chỉ có một loại dependency trong MVP (finish-to-start).
Data & State ChangesTask Dependency.
Acceptance Criteria
  • TASK-DEPENDENCY-001-AC01 Given A → B → C, When thêm C → A, Then bị từ chối và hiển thị chuỗi A → B → C → A.
  • TASK-DEPENDENCY-001-AC02 Given B phụ thuộc A, When xóa A, Then System yêu cầu xử lý dependency của B trước khi xóa.
Dependencies5.2 invariant, PLAN-GENERATE-001

9.7. Execution Labels

Confirmed (outline, 20.1): nhãn Available for agent và Manual editor requirement; cần định nghĩa cách gán, quyền ghi đè và cách thực thi.

TASK-LABEL-001 — Gán, ghi đè và thực thi execution label

Priority · ConfirmationP0 · Confirmed (nhãn), Assumption (quy tắc)
PurposePhân định rõ việc agent được làm và việc Researcher bắt buộc tự làm.
ActorOrchestrator (đề xuất), Researcher (quyết định), System (thực thi)
Preconditions—
TriggerTạo Task; sửa label; kích hoạt Task.
Main Flow
  1. Gán: Orchestrator đề xuất label kèm lý do khi tạo Plan (6.4). Đề xuất Manual editor requirement khi Task cần phán đoán chuyên môn của tác giả, thao tác ngoài hệ thống, dữ liệu thực nghiệm, hoặc đóng góp mà tính liêm chính học thuật đòi hỏi tác giả tự làm.
  2. Ghi đè: trước khi duyệt, Researcher sửa label tự do trong Draft. Sau khi duyệt, đổi label là thay đổi lớn (MC-06) qua Plan Version mới (APR-10).

Business RulesMọi đổi label sau khi duyệt, kể cả từ manual sang agent, là thay đổi lớn MC-06: tạo Plan Version mới, bắt buộc ghi lý do và chỉ có hiệu lực sau APR-01 (OQ-016 đã chốt). Label hiển thị khác biệt rõ ở mọi màn hình (15.5).
Data & State ChangesĐịnh nghĩa Task; Plan Version; Audit Event.
Acceptance Criteria
  • TASK-LABEL-001-AC01 Given Task manual In Progress, When có yêu cầu tạo Workflow task_execution cho Task đó, Then System từ chối.
  • TASK-LABEL-001-AC02 Given baseline có Task manual, When Researcher đổi label sang agent, Then một Plan Version Draft mới được tạo và đổi chỉ có hiệu lực sau APR-01.
  • TASK-LABEL-001-AC03 Given Plan đề xuất, When xem Task, Then mỗi Task có label và lý do đề xuất.
DependenciesWF-03, PLAN-IMPACT-001, 15.5
Open Questions—
