2.1. MVP Scope

Định nghĩa MVP

MVP là bản phát hành đầu tiên giúp một nhà nghiên cứu cá nhân, trên web application, đi hết một vòng nghiên cứu trong cùng sản phẩm:

tạo Research Project → làm rõ ngữ cảnh với Orchestrator → nhận và phê duyệt Plan → chọn và thực thi từng Task → tìm và duyệt tài liệu → tổng hợp evidence → viết bản thảo LaTeX có citation truy vết được → quay lại sau gián đoạn mà không mất trạng thái.

Vòng này tương ứng với bảy workflow bắt buộc WF-01–WF-07. MVP chỉ được coi là đạt khi cả bảy workflow chạy được theo acceptance criteria ở mục 19.

Confirmed — web application, individual researchers first (21.1); bảy workflow bắt buộc (outline mục 6). Câu “MVP chỉ đạt khi cả bảy workflow chạy được”: Confirmed — PO duyệt 31/10/2026 (PC-01).

Mục tiêu: người dùng luôn biết các agent đang làm gì, vì sao đang chờ, và can thiệp được đúng lúc. Thực thi multi-agent không được là một “hộp đen” chỉ trả về kết quả cuối.

Confirmed — người dùng yêu cầu 29/10/2026: có giao diện giám sát và theo dõi các agent làm việc cùng nhau. Danh sách chức năng bên dưới: Confirmed — PO duyệt 31/10/2026 (PC-01).

Quy tắc cho API key và kết nối (Confirmed — PO chốt 31/10/2026 (PC-01, OQ-014); chi tiết ở mục 16–17):

  • Người dùng tự cung cấp API key cho mọi Provider Connection. Hệ thống không cấp key hay hạn mức mặc định. Chưa có Provider Connection hợp lệ thì không chạy được Agent Run.
  • MVP chỉ hỗ trợ ba provider: OpenAI, Anthropic Claude, Google Gemini. Base URL được đổi (proxy, gateway, model tự host) nhưng phải tương thích API chính thức của provider được chọn; kiểm tra kết nối thất bại thì không lưu kết nối ở trạng thái hợp lệ.
  • Nhập base URL và API key của nhà cung cấp bất kỳ, kèm endpoint kiểm tra hạn mức và tiêu thụ, thuộc FUT-05. MVP chỉ ghi và hiển thị usage theo NFR-USAGE-001–003, không giới hạn ngân sách (PC-01, OQ-077).
  • API key phải được lưu mã hóa. Sau khi lưu chỉ hiển thị dạng che, ví dụ vài ký tự cuối; không hiển thị lại toàn bộ.
  • API key không được đưa vào Shared Context, prompt, artifact, log hay nội dung gửi cho agent. Audit trail chỉ ghi sự kiện tạo, sửa, xóa kết nối, không ghi giá trị key.
  • API key thuộc tài khoản người dùng và không dùng chung giữa các tài khoản.
  • Nếu agent cần cho một Task chưa được gán kết nối hợp lệ, readiness check chặn Task và nêu rõ lý do (9.5). Lỗi provider khi đang chạy xử lý theo 8.5.
  • Khi đổi model hoặc kết nối, Agent Run đang chạy giữ cấu hình cũ; thay đổi áp dụng từ Agent Run tiếp theo. Provider và model thực tế được ghi vào provenance của từng Agent Run.
  • Hệ thống chuẩn hóa khác biệt giữa các provider (tool calls, lỗi, usage) theo 8.6. Khi model được chọn thiếu năng lực agent cần, ví dụ tool calling, hệ thống cảnh báo lúc gán.

Không thuộc Settings của MVP: bật/tắt các điểm duyệt bắt buộc, quản lý nhóm và thành viên, thanh toán, đổi mật khẩu hoặc phương thức đăng nhập (do eTroy quản lý). Không có tham số nâng cao của model (temperature, giới hạn token…) và hệ thống không cung cấp key hay hạn mức mặc định (Confirmed — PO chốt 31/10/2026 (PC-01, OQ-014, OQ-015)).

  • Deployment: cloud do đội phát triển vận hành; vùng lưu trữ dữ liệu chốt khi chọn hạ tầng (Confirmed — PO chốt 31/10/2026 (PC-01, OQ-091)).
