18. Data and State Specifications

Trạng thái biên soạn: Đã duyệt — bản cuối 31/10/2026 (phiếu chốt PC-01) · Cơ sở: outline đã chốt, mục 3, 5, 6, mục 20.1

Mục này chi tiết hóa domain model ở mục 5 thành schema logic, enumeration, bảng chuyển trạng thái, quy tắc phiên bản, idempotency và kiểm tra dữ liệu. Schema là logic: kiểu dữ liệu, bảng lưu trữ và công nghệ database là quyết định kỹ thuật. Tên entity và trạng thái giữ nguyên mục 5. Giải quyết SYNC-05, SYNC-11, BL-03-06, BL-03-07. Priority do biên soạn đề xuất theo tiêu chí 2.4 (OQ-011) và được PO duyệt ngày 31/10/2026 (DEC-44, bảng tổng hợp ở 2.4). Toàn bộ chi tiết là Assumption trừ khi dẫn từ quyết định đã xác nhận; các trường và trạng thái theo PC-01 (OQ-015, OQ-030, OQ-061, OQ-062, OQ-073, OQ-078, OQ-092) ghi nguồn tại chỗ. Bảng Open Questions ở 18.7.

Workflow, Workflow Step, Agent Run

Entity Chuyển trạng thái (Từ → Đến: trigger, actor)
WorkflowCreated → Running: System bắt đầu. Running → Waiting for User: prompt chặn mở. Waiting for User → Running: trả lời. Running → Paused: Researcher tạm dừng. Paused → Running: Researcher tiếp tục. Running → Interrupted: System phát hiện dừng ngoài ý muốn. Interrupted → Running: Recovery decision “tiếp tục”/“chạy lại bước” (Researcher). Running → Succeeded: mọi bước xong. Running → Failed: bước Failed hết chính sách thử lại. Running, Waiting for User, Paused, Interrupted → Cancelled: Researcher hủy. Bản ghi provenance

Mọi dữ liệu do agent tạo (ArtifactVersion, Evidence, Claim, ChangeProposal, DiscoveredResult, PlanVersion do Orchestrator tạo) mang Provenance:

Trường Nội dung
createdBy*ActorRef (agent kèm agentRunId, hoặc researcher, hoặc system).
workflowId, stepId, taskId, planVersionIdNgữ cảnh điều phối và nghiên cứu khi tạo.

provider, modelLấy từ Agent Run (INT-PROVIDER-006).

Quy tắc

  • Phê duyệt gắn với objectVersion; nếu đối tượng đổi sau khi duyệt thì phê duyệt không áp dụng cho bản mới (3.4).
  • Mọi chuyển trạng thái ghi một AuditEvent có actor, fromState, toState (Confirmed — OQ-004, giải quyết SYNC-11).
  • Khi đầu vào trong provenance bị thay đổi, thu hồi hoặc chuyển Stale, System lan truyền cờ needsReview tới Task, Claim và Change Proposal phụ thuộc (9.11, 10.8).
  • Không có entity thành viên project; ActorRef researcher luôn là chủ tài khoản trong MVP (OWN-06).

18.5. Data Validation

Ràng buộc duy nhất

  • Một ResearchPlan mỗi project; tối đa một Manuscript mỗi project.
  • Mỗi ResearchPlan: tối đa một PlanVersion Approved; tối đa một PlanVersion ở Draft hoặc Proposed.
  • Mỗi Task: tối đa một Workflow ở trạng thái chưa kết thúc.
  • Mỗi Artifact: tối đa một ArtifactVersion Accepted.
  • Mỗi Reference: tối đa một SourceDocument. bibtexKey duy nhất trong tài khoản. DOI trùng trong tài khoản được cảnh báo và đề xuất gộp (không chặn cứng, vì metadata nguồn có thể sai).
  • ProjectReferenceSelection Active duy nhất theo (projectId, referenceId).
  • ManuscriptFile Active duy nhất theo (manuscriptId, path); BibliographyEntry duy nhất theo (manuscriptId, bibtexKey).
  • ProviderConnection.name duy nhất trong tài khoản; AgentModelAssignment duy nhất theo (accountId, agent, instance) (DEC-50).
  • Prompt có tối đa một response.
  • Account.authIdentity (issuer, subject) duy nhất toàn hệ thống: một định danh eTroy ứng với đúng một tài khoản SIRes (OQ-073).

Toàn vẹn tham chiếu

  • OWN-01–OWN-03 (5.10) được kiểm tra khi ghi: mọi ref cùng accountId; ref cấp project cùng projectId.
  • Evidence chỉ tham chiếu Reference đang Trusted và được chọn Active cho project tại thời điểm tạo.
  • BibliographyEntry chỉ tham chiếu Reference Trusted.
  • Không xóa vật lý entity còn được tham chiếu bởi provenance, ApprovalRecord hoặc AuditEvent (OWN-05).
  • AgentModelAssignment chỉ tham chiếu ProviderConnection cùng tài khoản; model phải thuộc availableModels hoặc được người dùng nhập và kiểm tra.

Kiểm tra cấu trúc Plan Version (trước khi trình duyệt)

  • Đồ thị TaskDependency không có chu trình; mọi dependsOnTaskId thuộc cùng Plan Version.
  • Mỗi TaskDefinition có objective, ít nhất một expectedOutput bắt buộc, ít nhất một acceptance criterion và executionLabel hợp lệ.
  • Mỗi Task thuộc một Phase của cùng version.

Trường bắt buộc và định dạng

  • Trường đánh dấu * ở 18.1 bắt buộc. Enumeration chỉ nhận giá trị liệt kê ở 18.2.
  • baseUrl là URL tuyệt đối hợp lệ, dùng HTTPS (NFR-TRANSIT-001) và tương thích API chính thức của provider đã chọn (INT-PROVIDER-005, OQ-014).
  • googleScholarProfileUrl, nếu có, là URL tuyệt đối hợp lệ dùng HTTPS (OQ-015).
  • File tài liệu để index: chỉ PDF có lớp văn bản, tối đa 50 MB mỗi file (OQ-050, PC-01; INT-DOC-001). Độ dài văn bản và dung lượng file khác có giới hạn cấu hình; vượt giới hạn trả lỗi rõ ràng, không cắt ngầm.
  • Giá trị trong VerificationThresholds nằm trong miền hợp lệ do hệ thống quy định; Researcher khôi phục được giá trị mặc định (OQ-092).
  • reasonCode bắt buộc khi trả lại hoặc chặn Task (KPI-04).

Acceptance criteria

  • DATA-STATE-001-AC01 — Given Task ở Ready, When có yêu cầu chuyển thẳng sang Completed, Then bị từ chối và Task giữ Ready.
  • DATA-STATE-001-AC02 — Given Plan Version Proposed được duyệt, When giao dịch hoàn tất, Then bản này Approved, baseline cũ Superseded, và không tồn tại hai bản Approved.
  • DATA-STATE-001-AC03 — Given project Archived bị xóa mềm 31 ngày trước, When Researcher gọi API khôi phục, Then bị từ chối vì đã quá hạn khôi phục; Given xóa mềm 5 ngày trước, Then project trở về Archived.
  • DATA-IDEMP-001-AC01 — Given Researcher nhấn Thực thi hai lần với cùng idempotencyKey, When hệ thống xử lý, Then chỉ có một Workflow được tạo.
  • DATA-IDEMP-002-AC01 — Given hai yêu cầu kích hoạt cùng Task đồng thời với khóa khác nhau, When xử lý, Then một yêu cầu thành công, yêu cầu còn lại bị từ chối vì Task đã có Workflow hoạt động.
  • DATA-IDEMP-003-AC01 — Given workflow bị hủy khi Agent Run đang chạy, When Agent Run trả kết quả sau đó, Then Agent Run được đánh dấu discarded và không Artifact Version mới nào được tạo.
  • DATA-PROV-001-AC01 — Given Synthesis Agent tạo bản tổng hợp, When mở provenance, Then thấy agentRunId, provider, model, danh sách evidence và reference đã dùng.
  • DATA-AUDIT-001-AC01 — Given Researcher thu hồi một Reference, When xem Activity and History, Then có AuditEvent với actor researcher, Trusted → Revoked và lý do.
  • DATA-VALID-001-AC01 — Given Plan Version Draft có chu trình T1 → T2 → T1, When trình duyệt, Then bị từ chối và nêu T1, T2.
  • DATA-STATE-002-AC01 — Given Plan Version Approved, When Researcher gọi API sửa trực tiếp nội dung, Then bị từ chối phía server và gợi ý tạo Draft mới.
  • DATA-PERSIST-001-AC01 — Given lỗi xảy ra sau khi ghi chuyển trạng thái nhưng trước khi ghi AuditEvent, When giao dịch kết thúc, Then cả hai đều không được ghi và không có sự kiện nào được phát.
  • DATA-PERSIST-002-AC01 — Given bước vừa Succeeded, When đọc checkpoint mới nhất, Then checkpoint chứa bước đó và outputRefs của nó.
  • DATA-IDEMP-004-AC01 — Given provider trả timeout một lần rồi thành công, When xem lịch sử, Then chỉ có một Agent Run với attempts = 2; Given Agent Run Failed và Researcher chạy lại bước, Then có Agent Run mới.
  • DATA-IDEMP-005-AC01 — Given yêu cầu build hai lần cùng revision và cùng cấu hình, When xử lý, Then chỉ có một Build được chạy và yêu cầu thứ hai nhận kết quả của Build đó.
  • DATA-STORE-001-AC01 — Given tải lên hai lần cùng một file PDF, When lưu, Then kho đối tượng chỉ giữ một bản theo contentHash và cả hai tham chiếu trỏ tới bản đó.
  • DATA-CONC-001-AC01 — Given hai tab cùng sửa một Plan Version Draft, When tab thứ hai lưu sau, Then nhận lỗi xung đột và nội dung tab thứ nhất không bị ghi đè.
