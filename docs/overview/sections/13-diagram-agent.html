13. Functional Requirements — Diagram Agent

Trạng thái biên soạn: Đã duyệt — bản cuối 31/10/2026 (phiếu chốt PC-01) · Cơ sở: outline đã chốt, mục 1–6

Mục này đặc tả việc tạo sơ đồ bằng Diagram Agent theo WF-07. Diagram generation là năng lực SCOPE-10 thuộc MVP (OQ-009 đã chốt). Danh mục năng lực lấy từ outline (Confirmed); luồng, quy tắc và acceptance criteria do biên soạn đề xuất (Assumption), đã được PO duyệt nội dung trong phiếu chốt PC-01 (31/10/2026). Priority do biên soạn đề xuất theo tiêu chí 2.4 (OQ-011) và được PO duyệt ngày 31/10/2026 (DEC-44, bảng tổng hợp ở mục 20). Diagram lưu dưới dạng Artifact loại diagram (5.7).

13.1. Diagram Generation

Confirmed (outline): tạo sơ đồ Mermaid hoặc UML từ yêu cầu Task và context đã duyệt.

DIAG-GEN-001 — Tạo sơ đồ từ yêu cầu

Priority · ConfirmationP0 ·Confirmed (năng lực), Assumption (chi tiết)
PurposeMinh họa quy trình, kiến trúc, mô hình nghiên cứu bằng sơ đồ chỉnh sửa được.
ActorDiagram Agent; Orchestrator (lắp ráp context); Researcher
PreconditionsCó Task đã kích hoạt cần sơ đồ, hoặc Researcher yêu cầu trong Project AI Chat với active task; Diagram Agent có Agent Model Assignment hợp lệ.
TriggerWF-07.S1.
Main Flow
  1. Orchestrator xác định loại sơ đồ (13.2) từ yêu cầu; nếu không rõ, hỏi bằng prompt choice.
  2. Orchestrator lắp ráp context: yêu cầu Task, artifact Accepted và claim liên quan, mô tả của Researcher (14.2).
  3. Diagram Agent tạo nguồn sơ đồ Mermaid kèm tiêu đề và mô tả ngắn các thành phần.
  4. Chuyển sang kiểm tra (DIAG-VALIDATE-001) và lưu (DIAG-SOURCE-001).
Alternative / Error FlowsContext không đủ để vẽ (ví dụ thiếu các bước của quy trình): Diagram Agent nêu phần thiếu qua prompt information_request, không tự bịa thành phần.
Business RulesSơ đồ chỉ dùng thông tin trong context được cấp; thành phần do agent giả định phải được ghi trong mô tả. Diagram Agent không ghi vào bản thảo (3.3).
Data & State ChangesAgent Run; Artifact Version Draft loại diagram.
Acceptance Criteria
  • DIAG-GEN-001-AC01 Given Task yêu cầu sơ đồ quy trình có ba bước đã mô tả trong artifact accepted, When Diagram Agent hoàn tất, Then sơ đồ có đúng các bước đó và artifact ghi Task và Agent Run tạo ra.
  • DIAG-GEN-001-AC02 Given yêu cầu không xác định được loại sơ đồ, When bắt đầu, Then Researcher nhận prompt chọn loại trước khi agent tạo nguồn.
DependenciesCTX-ASSEMBLY-001; AGENT Diagram (8.2)
Open Questions—

13.2. Supported Diagram Types

Confirmed (outline): sequence, component, activity, state và workflow diagram khi phù hợp. Ánh xạ cú pháp: Assumption.

DIAG-TYPES-001 — Loại sơ đồ hỗ trợ

Priority · ConfirmationP0 ·Confirmed (năm loại), Assumption (cú pháp)
PurposeGiới hạn rõ loại sơ đồ MVP hỗ trợ để kiểm tra và render được một cách xác định.
ActorOrchestrator (chọn loại), Diagram Agent, System
PreconditionsDIAG-GEN-001 đang chạy.
TriggerWF-07.S1 xác định loại sơ đồ.
Main FlowOrchestrator ánh xạ yêu cầu vào một trong năm loại ở bảng trên → Diagram Agent tạo nguồn bằng cú pháp tương ứng.
Alternative / Error FlowsYêu cầu khớp nhiều loại: hỏi Researcher bằng prompt choice (DIAG-GEN-001).
Business RulesMVP chỉ dùng Mermaid cho cả năm loại; PlantUML để sau MVP (Chốt (biên soạn 30/10/2026; PO duyệt 31/10/2026, PC-01)). Yêu cầu loại sơ đồ ngoài danh sách: Diagram Agent báo không hỗ trợ và đề xuất loại gần nhất.
Data & State ChangesLoại sơ đồ và cú pháp ghi trong Artifact Version.
Acceptance Criteria
  • DIAG-TYPES-001-AC01 Given yêu cầu state diagram, When tạo, Then nguồn dùng Mermaid stateDiagram-v2 và qua kiểm tra cú pháp.
  • DIAG-TYPES-001-AC02 Given yêu cầu loại không hỗ trợ (ví dụ Gantt), When xử lý, Then Researcher nhận thông báo không hỗ trợ kèm loại gợi ý.
DependenciesDIAG-GEN-001; INT 17.5
Open Questions—

13.3. Editable Source and Preview

Confirmed (outline): lưu mã nguồn, preview, version và Task liên quan.

DIAG-SOURCE-001 — Lưu nguồn, preview và phiên bản

Priority · ConfirmationP0 ·Confirmed (năng lực), Assumption (chi tiết)
PurposeSơ đồ luôn chỉnh sửa được từ nguồn và truy vết được về Task và phiên bản.
ActorSystem; Researcher
PreconditionsDiagram Agent hoặc Researcher vừa tạo hoặc sửa nguồn sơ đồ.
TriggerWF-07.S4; Researcher lưu nguồn đã sửa (WF-07.S5).
Main FlowMỗi Artifact Version diagram lưu: cú pháp (Mermaid trong MVP), mã nguồn, preview đã render (SVG), trạng thái kiểm tra, Task, Agent Run hoặc actor Researcher. Researcher mở editor nguồn cạnh preview; lưu sửa tạo version mới.
Alternative / Error FlowsRender preview thất bại: vẫn lưu version với nguồn và trạng thái kiểm tra lỗi (DIAG-VALIDATE-001).
Business RulesMã nguồn là bản chính; preview luôn được render lại từ nguồn của cùng version, không sửa riêng. Version bất biến (5.7).
Data & State ChangesArtifact Version loại diagram (nguồn, preview SVG, trạng thái kiểm tra).
Acceptance Criteria
  • DIAG-SOURCE-001-AC01 Given Researcher sửa nguồn và lưu, When xem lịch sử, Then có version mới với actor Researcher và version cũ không đổi.
  • DIAG-SOURCE-001-AC02 Given một version diagram, When mở, Then thấy cả nguồn và preview khớp với nguồn đó.
DependenciesCTX-REGISTRY-001; INT 17.5

13.4. Validation

Confirmed (outline): phát hiện lỗi cú pháp và báo lỗi render.

DIAG-VALIDATE-001 — Kiểm tra cú pháp và render

Priority · ConfirmationP0 ·Confirmed (năng lực), Assumption (chi tiết)
PurposeKhông sơ đồ lỗi nào được chấp nhận hay đưa vào bản thảo.
ActorSystem; Diagram Agent
PreconditionsCó nguồn sơ đồ mới hoặc vừa sửa.
TriggerWF-07.S3; mỗi lần lưu nguồn.
Main FlowSystem phân tích cú pháp nguồn bằng trình phân tích Mermaid → hợp lệ thì render preview → lỗi cú pháp: trả thông điệp lỗi (dòng, mô tả) cho Diagram Agent sửa, trong giới hạn thử lại (WF-07.E1) → vẫn lỗi: lưu Draft kèm lỗi cho Researcher sửa tay.
Alternative / Error FlowsCú pháp đúng nhưng render lỗi (quá lớn, quá thời gian): lưu nguồn, báo lỗi render (WF-07.E2).
Business RulesKiểm tra cú pháp là xác định, không dựa vào model. Diagram có lỗi không chấp nhận được (DIAG-REVIEW-001). Diagram Agent tự sửa lỗi cú pháp tối đa 2 lần (mỗi lần một Agent Run mới), tương ứng giới hạn Agent Run mới của Orchestrator ở 8.5.
Data & State ChangesTrạng thái kiểm tra (valid, syntax_error, render_error) và preview trong Artifact Version; Agent Run cho các lượt tự sửa.
Acceptance Criteria
  • DIAG-VALIDATE-001-AC01 Given nguồn Mermaid có lỗi cú pháp, When kiểm tra, Then hiển thị dòng lỗi và mô tả; không render preview cũ như thể hợp lệ.
  • DIAG-VALIDATE-001-AC02 Given Diagram Agent hết lượt tự sửa, When kết thúc, Then artifact Draft được lưu với trạng thái kiểm tra lỗi.
DependenciesINT 17.5
Open Questions—

13.5. Human Review

Confirmed (outline): người dùng sửa sơ đồ và duyệt trước khi đưa vào sản phẩm cuối. APR-07 (3.1).

DIAG-REVIEW-001 — Researcher duyệt sơ đồ

Priority · ConfirmationP0 ·Confirmed (năng lực, APR-07), Assumption (chi tiết)
PurposeSơ đồ chỉ vào sản phẩm cuối khi Researcher đồng ý (APR-07).
ActorResearcher
PreconditionsArtifact diagram có version Draft.
TriggerWF-07.S5; Task chứa sơ đồ vào In Review.
Main FlowResearcher xem preview và nguồn → sửa trực tiếp, yêu cầu Diagram Agent sửa (kèm chỉ dẫn, tạo version mới), chấp nhận (Accepted) hoặc từ chối (Rejected) → version accepted mới làm version cũ Superseded.
Alternative / Error FlowsResearcher từ chối: version → Rejected; có thể yêu cầu Diagram Agent tạo lại kèm chỉ dẫn.
Business RulesChỉ version qua kiểm tra cú pháp và render mới chấp nhận được. Chỉ diagram Accepted được chèn vào bản thảo (MS-DIAGRAM-001) hoặc dùng làm đầu vào Task khác.
Data & State ChangesArtifact Version → Accepted/Rejected; version accepted cũ → Superseded; Audit Event APR-07.
Acceptance Criteria
  • DIAG-REVIEW-001-AC01 Given diagram có lỗi cú pháp, When Researcher chấp nhận, Then System từ chối.
  • DIAG-REVIEW-001-AC02 Given Diagram Agent, When cố chuyển version sang Accepted, Then System từ chối và ghi Audit Event.
DependenciesDIAG-VALIDATE-001; MS-DIAGRAM-001
Open Questions—
