16.1. Security and Privacy

Mã Phát biểu Chỉ tiêu Kiểm chứng
NFR-AUTH-001Mọi truy cập vào dữ liệu và chức năng phải qua authentication. Authentication duy nhất qua SSO của tổ chức bằng eTroy OIDC (INT-OIDC-001, 17.7); SIRes thuộc nền tảng eTroy và quản lý người dùng do eTroy đảm nhận. Không có đăng ký email/mật khẩu riêng, không đăng nhập OAuth Google. SIRes không lưu mật khẩu; phiên đăng nhập dựa trên token do eTroy OIDC cấp (Confirmed — PO chốt 31/10/2026 (PC-01, OQ-073)). Chi tiết claim dùng (họ tên, email ban đầu) và vòng đời phiên là Assumption (ASM-13).0 endpoint dữ liệu truy cập được khi chưa đăng nhập; 0 mật khẩu người dùng lưu trong SIRes.Quét tự động toàn bộ endpoint không kèm phiên đăng nhập; review schema dữ liệu tài khoản.
NFR-AUTHZ-001Authorization được kiểm tra phía server cho mọi yêu cầu, theo permission matrix 3.5 và quyền theo trạng thái 18.2. Không dựa vào việc giao diện ẩn nút.100% thao tác ghi kiểm tra quyền và trạng thái trước khi thực hiện.Test API trực tiếp với yêu cầu vượt quyền (agent tự phê duyệt, nghiệm thu Task không ở In Review…).
NFR-ISOL-001Cách ly tài khoản và project (3.4): truy cập tài nguyên của tài khoản khác trả về “không tìm thấy”, không tiết lộ sự tồn tại.0 rò rỉ chéo tài khoản; 0 dữ liệu project khác trong context gửi provider.Test cách ly tự động (19.12); kiểm tra context đã lắp ráp chỉ chứa định danh của project đang thực thi.
NFR-SECRETS-001API key của Provider Connection được mã hóa khi lưu bằng khóa do hệ thống quản lý khóa riêng (không lưu cùng dữ liệu); chỉ giải mã trong provider adapter tại thời điểm gọi.0 API key ở dạng rõ trong database, log, Shared Context, prompt, artifact, Audit Event, thông báo lỗi.Quét log và dữ liệu sau bộ test có key mẫu đã biết; review mã adapter.
NFR-SECRETS-002Sau khi lưu, API key chỉ hiển thị dạng che (tối đa 4 ký tự cuối). Không có API trả về key đầy đủ cho client.Như phát biểu.Test API và giao diện Settings.
NFR-SECRETS-003Xóa hoặc thay API key có hiệu lực cho mọi Agent Run bắt đầu sau thời điểm đó; key cũ bị xóa khỏi kho lưu trữ.Agent Run mới không dùng key cũ.Test: xóa key rồi kích hoạt Task dùng agent đó → readiness chặn.
NFR-TRANSIT-001Mọi kết nối giữa trình duyệt và server, và giữa server với provider/dịch vụ ngoài, dùng TLS. Base URL tùy chỉnh (proxy, gateway, model tự host tương thích API chính thức của provider, OQ-014) không dùng HTTPS bị từ chối.100% lưu lượng ra ngoài qua TLS (trừ ngoại lệ được PO duyệt).Kiểm tra cấu hình; test tạo Provider Connection với URL http.
NFR-PRIV-001Người dùng được thông báo rõ rằng nội dung gửi cho agent sẽ được gửi tới provider họ đã cấu hình. Chỉ context do Orchestrator lắp ráp cho Agent Run được gửi. Trong thông tin cá nhân, chỉ lĩnh vực nghiên cứu được đưa vào context, và chỉ khi người dùng bật công tắc tương ứng trong Settings (OQ-015, PC-01).Thông báo hiển thị khi tạo Provider Connection đầu tiên.Review giao diện; kiểm tra context mẫu.
NFR-SANDBOX-001Build LaTeX và render sơ đồ chạy trong môi trường cô lập: không truy cập mạng, không shell-escape, giới hạn CPU, bộ nhớ, thời gian và dung lượng; mỗi build một workspace riêng.Build hoặc render vượt 120 giây hoặc 2 GB bộ nhớ bị dừng và báo lỗi rõ ràng; người vận hành cấu hình được giới hạn (Chốt (biên soạn 30/10/2026; PO duyệt 31/10/2026, PC-01)).Test với tài liệu cố gắng đọc file hệ thống, gọi mạng, vòng lặp vô hạn.

Acceptance criteria

  • NFR-AUTH-001-AC01 — Given không có phiên đăng nhập, When gọi bất kỳ endpoint dữ liệu nào, Then nhận lỗi yêu cầu đăng nhập và không có dữ liệu trả về.
  • NFR-AUTH-001-AC02 — Given người dùng chưa đăng nhập mở SIRes, When chọn đăng nhập, Then được chuyển tới eTroy OIDC; giao diện SIRes không có form email/mật khẩu hay nút đăng nhập Google.
  • NFR-SECRETS-002-AC01 — Given đã lưu API key, When mở Settings hoặc gọi API đọc Provider Connection, Then chỉ thấy tối đa 4 ký tự cuối của key.
  • NFR-SECRETS-003-AC01 — Given đã xóa API key của kết nối mà Synthesis Agent dùng, When kích hoạt Task cần Synthesis Agent, Then readiness không đạt và không Agent Run nào dùng key cũ.
  • NFR-TRANSIT-001-AC01 — Given tạo Provider Connection với base URL http://, When lưu, Then hệ thống từ chối lưu và nêu lý do yêu cầu HTTPS.
  • NFR-PRIV-001-AC01 — Given người dùng tạo Provider Connection đầu tiên, When lưu, Then thông báo về việc gửi nội dung tới provider hiển thị và cần xác nhận đã đọc.
  • NFR-SECRETS-001-AC01 — Given Provider Connection lưu key mẫu “sk-test-KNOWN”, When chạy một Task agent và tìm chuỗi đó trong log, database dạng rõ, Audit Event và context đã gửi, Then không tìm thấy.
  • NFR-AUTHZ-001-AC01 — Given Task ở trạng thái In Progress, When gọi API nghiệm thu Task trực tiếp, Then yêu cầu bị từ chối và trạng thái không đổi.
  • NFR-ISOL-001-AC01 — Given tài khoản A, When mở URL project của tài khoản B, Then nhận “không tìm thấy” giống như project không tồn tại.
  • NFR-SANDBOX-001-AC01 — Given file .tex cố đọc /etc/passwd qua \input, When build, Then build thất bại hoặc không đọc được file ngoài workspace.

16.2. Reliability and Durability

Mã Phát biểu Chỉ tiêu Kiểm chứng
NFR-DUR-001Mọi thay đổi trạng thái được xác nhận cho người dùng chỉ sau khi đã ghi bền vững; chuyển trạng thái và Audit Event ghi trong cùng một giao dịch (18.4).0 thay đổi đã xác nhận bị mất khi server khởi động lại.Fault injection: dừng tiến trình ngay sau khi xác nhận.
NFR-REC-001Workflow lưu checkpoint sau mỗi bước hoàn tất và trước mỗi điểm chờ người dùng; workflow dừng ngoài ý muốn được phát hiện và chuyển Interrupted.Phát hiện trong ≤ 2 phút kể từ heartbeat cuối (Chốt (biên soạn 30/10/2026; PO duyệt 31/10/2026, PC-01), CTX-RECOVERY-001); KPI-03 ≥ 99% (Confirmed).Fault injection ở từng loại bước; đo theo 16.9.
NFR-REC-002Không chạy lại tự động bước có tác động (gọi provider, ghi dữ liệu) sau gián đoạn khi chưa có Recovery decision (WF-06).0 trường hợp chạy lại không có xác nhận.Kiểm tra Audit Event sau fault injection.
NFR-AVAIL-001Dịch vụ sẵn sàng liên tục cho người dùng; thời gian bảo trì được báo trước trong ứng dụng.99,5% mỗi tháng, không tính bảo trì báo trước (Confirmed — PO chốt 31/10/2026 (PC-01, OQ-075)).Giám sát uptime.
NFR-BACKUP-001Dữ liệu được sao lưu định kỳ và khôi phục được.RPO ≤ 24 giờ, RTO ≤ 8 giờ (Confirmed — PO chốt 31/10/2026 (PC-01, OQ-075)).Diễn tập khôi phục mỗi quý.

Mô hình triển khai: Confirmed — PO chốt 31/10/2026 (PC-01, OQ-091). MVP triển khai trên cloud do đội phát triển vận hành; đội phát triển chịu trách nhiệm uptime, sao lưu và diễn tập khôi phục ở bảng trên. Vùng lưu trữ dữ liệu được chốt khi chọn hạ tầng.

Acceptance criteria

  • NFR-REC-001-AC01 — Given workflow đang ở bước 3/5, When tiến trình worker bị dừng đột ngột, Then workflow chuyển Interrupted và đầu ra bước 1–2 còn nguyên khi khôi phục.
  • NFR-DUR-001-AC01 — Given Researcher vừa duyệt Plan và nhận xác nhận, When server khởi động lại, Then Plan Version vẫn Approved và có Audit Event tương ứng.
  • NFR-REC-002-AC01 — Given workflow chuyển Interrupted, When chưa có Recovery decision, Then không có Agent Run mới và không có lời gọi provider nào cho workflow đó.
  • NFR-AVAIL-001-AC01 — Given số liệu giám sát uptime của một tháng, When tính tỷ lệ sẵn sàng không tính bảo trì báo trước, Then đạt ≥ 99,5%.
  • NFR-BACKUP-001-AC01 — Given bản sao lưu gần nhất, When diễn tập khôi phục vào môi trường trống, Then dữ liệu được khôi phục trong ≤ 8 giờ (RTO) và dữ liệu mất không quá 24 giờ (RPO).

16.10. Evaluation và Eval Trace

Confirmed — PO duyệt 31/10/2026 (DEC-46); bổ sung sau phiếu PC-01, Priority P1. Giá trị nhãn evidence và dung sai hồi quy: DEC-45. Phạm vi: thời điểm thiết kế và phát triển, trên bộ dữ liệu nghiệm thu (19.14). MVP không thu Eval Trace từ dữ liệu người dùng (FUT-06, 2.3).

Trace vận hành và Eval Trace khác nhau. Trace vận hành (NFR-OBS-001, NFR-OBS-004) chạy trên production, chỉ chứa metadata và dùng để gỡ lỗi, theo dõi độ trễ và tính KPI. Eval Trace chạy offline trên dữ liệu của đội phát triển, chứa đủ đầu vào và đầu ra của Agent Run, và dùng để chấm chất lượng agent: retrieval có tìm đúng evidence không, Synthesis Agent có viết claim vượt quá evidence không, Verification Agent có chấm đúng không.

Lý do cần Eval Trace: KPI-01 đếm claim mà Verification Agent tự gán Supported hoặc Partially Supported, nên nếu Verification Agent chấm dễ dãi thì KPI-01 vẫn đạt. TS-13-08 kiểm tra điều này một lần khi nghiệm thu; 16.10 biến phép kiểm tra đó thành phép đo lặp lại được cho từng provider, model và phiên bản prompt.
