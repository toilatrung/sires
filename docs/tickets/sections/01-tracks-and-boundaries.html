1.4. Quy tắc ranh giới mã nguồn

Các quy tắc dưới bổ sung quy tắc cho người viết service ở kiến trúc 3.6; trích dẫn theo số, ví dụ “quy tắc 1.4.3”.

  1. Một PR chạm một luồng. Ngoại lệ: PR hợp đồng (sửa docs/api-design rồi sinh lại libs/ts/contracts) và PR của luồng dùng chung. CI báo khi PR chạm nhiều luồng (scripts/development/check-tracks.mjs).
  2. Không import mã của service khác. Service chỉ phụ thuộc libs/ và type sinh từ hợp đồng; không đọc database của service khác (kiến trúc 3.5).
  3. Hợp đồng trước, code sau (ADR-14, kiến trúc 3.6.1). Cần endpoint hay sự kiện mới của luồng khác thì báo PO để cập nhật hợp đồng (OQ-103); khi hợp đồng đã merge, luồng gọi viết stub theo type sinh ra và code tiếp, không chờ luồng kia hiện thực xong.
  4. Stub nằm ở phía gọi. Mỗi luồng tự viết stub cho service mình gọi, trong thư mục test của mình. Fake dùng chung (OIDC, broker, Model Gateway giả lập) do luồng platform giữ.
  5. Thư viện dùng chung chỉ đổi tương thích ngược. Đổi phá vỡ thì thêm API mới, đánh dấu API cũ deprecated; từng luồng tự chuyển trong thư mục của mình. Luồng platform không sửa mã service.
  6. Migration trong thư mục service, chỉ chạm database của service, theo thứ tự expand → migrate → contract (kiến trúc 6.10). DDL tham chiếu ở docs/database/ddl là chuẩn (DEC-57); lệch thì ghi DBQ, không tự đổi schema.
  7. Phụ thuộc gói khai báo trong package.json hoặc pyproject.toml của chính luồng. Phiên bản dùng chung khai báo một chỗ (pnpm catalog, ràng buộc uv) do luồng infra giữ. Xung đột ở pnpm-lock.yaml hay uv.lock không sửa tay: rebase rồi chạy lại pnpm install hoặc uv lock.
  8. Cấu hình triển khai riêng của service ở apps/<service>/deploy/values.yaml; chart chung ở infra/helm thuộc luồng infra.
  9. web chia theo khu vực tính năng (1.5): mỗi khu vực có thư mục, route và namespace i18n riêng, nên hai khu vực không sửa chung file dịch.
  10. Service lớn chia module con (1.6) để nhiều người làm cùng service mà ít đụng file của nhau.
  11. Nhánh mang tên luồng: <luồng>/<mô-tả-ngắn>, ví dụ library/bibtex-parser; vào main qua pull request.
  12. CODEOWNERS theo thư mục luồng được điền khi PO phân công. Trước đó, kiểm tra 1.4.1 chỉ cảnh báo, không chặn merge.
