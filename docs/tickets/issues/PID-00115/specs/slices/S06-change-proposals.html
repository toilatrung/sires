Một lát dọc làm xong và kiểm được độc lập, trong đúng luồng của ticket. Trạng thái thực hiện ghi ở report.md của Dev, không ghi ở đây. Sketch: designs/Manuscript-states.html khối 9–11.

Làm

  1. Nạp listChangeProposals (Proposed; Outdated của file đang mở). File có proposal Proposed mang nhãn “đề xuất” ở cây file; file thêm mới hiện dòng nét đứt (EC35).
  2. Hộp proposal (H11) viền đứt brand ngay trong editor tại hunk đầu tiên của file đang mở: “Change Proposal · tên agent (provenance.createdBy) · chip trạng thái của shell”; Task (stableKey qua getTask, liên kết /projects/{projectId}/tasks/{taskId}); số claim, evidence, file; diff của file (DiffHunk.lines theo unified diff: dòng “-” nền diff-removed, “+” nền brand-tint, dạng chữ thường — EC36); “File khác trong proposal” mở rộng được, mỗi file một diff và liên kết mở file; chip citation (“Citation: n/n phân giải” hoặc “Citation lỗi: key”), key lỗi đánh dấu trong dòng diff, mismatches liệt kê; chip claim theo supportStatus (getClaim), liên kết /projects/{projectId}/claims/{claimId}; “Xem evidence”. Nội dung file trong editor không đổi khi chưa chấp nhận.
  3. Chấp nhận (H12): “Chấp nhận cả proposal” (viền xanh) bật khi Proposed, citationCheck.passed đúng bằng true, không file nào của proposal có thay đổi chưa lưu; vô hiệu thì ghi lý do cạnh nút (EC30, EC23). Không có nút theo khối, không sửa diff. acceptChangeProposal với Idempotency-Key, một request khi bấm nhiều lần (EC34); 200 → cập nhật revision, tải lại file bị đổi; 409 base_revision_mismatch → tải lại, hiện Outdated, file không đổi (EC32); 409 citation_check_failed hoặc đã xử lý nơi khác → tải lại, hiện trạng thái mới, không tô lỗi đỏ (EC33).
  4. Từ chối: hộp xác nhận nêu bản thảo không đổi, không hoàn tác được, ô lý do tùy chọn → rejectChangeProposal.
  5. Outdated (H13): hộp viền đứt muted, nền ground; lý do “Hết hiệu lực: file đã đổi từ revision gốc sang hiện hành” (số gốc từ getManuscriptRevision(baseRevisionId), file là file của diff có updatedInRevision lớn hơn số gốc; không xác định được file thì ghi bản thảo đã đổi); không Chấp nhận, không Từ chối; “Yêu cầu tạo lại” mở hộp có chỉ dẫn soạn sẵn sửa được → sendMessage vào hội thoại project mới nhất (listConversations scope project; chưa có thì createConversation), kèm activeTaskId là Task của proposal, Idempotency-Key; 202 → “Đã gửi tới Orchestrator” và liên kết Project AI Chat; lỗi → giữ chỉ dẫn, hộp lỗi có mã (EC31, EC38). Mock hội thoại do khu vực project giữ, test override.
  6. Deep link ?proposal={proposalId}: getChangeProposal, mở file đầu tiên của diff, đưa focus tới hộp; không thấy → “Không tìm thấy proposal”; đã xử lý → mở file và hiện trạng thái (EC37).
  7. Sự kiện loại change_proposal → tải lại danh sách và proposal đang mở (EC39); đã nối lại, cần tải lại → tải lại (EC52). Mọi nút dùng được bằng bàn phím, hộp thoại trả focus khi đóng (EC55).
