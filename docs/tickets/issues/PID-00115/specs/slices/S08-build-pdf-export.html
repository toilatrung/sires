Làm

  1. “Build PDF” (nút chính duy nhất, H15): còn file chưa lưu thì lưu trước (S04), lưu lỗi hoặc xung đột thì dừng (EC44); startBuild với revision hiện hành; 202 hoặc 200 hiển thị Build trả về (EC45). Trạng thái cập nhật qua sự kiện loại build (getBuild của build đó), không polling; đã nối lại, cần tải lại → tải lại (EC52).
  2. Chip build trên thanh công cụ: kiểu do chip của shell theo BuildStatus; chữ theo Manuscript.html (vi “Build OK · HH:mm”, “Đang build · mm:ss”, “Build lỗi · HH:mm”, “Chờ build · mm:ss”; en “Build OK”, “Building”, “Build failed”, “Queued”). Queued hoặc Running: thẻ thao tác dài trong vùng PDF (“Đang build revision N · compiler”, System, thời gian đã chạy, thanh chạy lặp data-progress="indeterminate", “rời trang được, kết quả báo qua notification”); không làm nút “Hủy build” và dòng hoạt động gần nhất (N8; thiết kế đã bỏ). “Build PDF” vô hiệu kèm lý do khi đang build revision hiện hành, bật lại khi có revision mới hơn (EC46, EC25).
  3. Build log hai lớp (H16), tab Build log: tiêu đề “Build thất bại · HH:mm · revision N”, câu “Bản PDF trước (revision M) vẫn được giữ” khi có build Succeeded cũ hơn (listBuilds). Mỗi issue: tiêu đề và câu giải thích dịch theo BuildIssue.code trong namespace manuscript, dựng từ params (package, path, key, command, limit, reason; giá trị giữ nguyên văn) cho đủ 10 mã của danh mục (unbalanced_braces, undefined_control_sequence, missing_file, missing_package, undefined_citation, shell_escape_disabled, path_outside_manuscript, timeout, memory_limit, infrastructure_unavailable), file và dòng, “Đi tới file:dòng” mở file và đặt con trỏ; issue không có file → không liên kết; code chưa dịch → tiêu đề chung theo severity kèm mã (EC47). friendlyMessage (nếu có) hiện dưới câu, ghi rõ là gợi ý; code ngoài danh mục: thân câu là friendlyMessage (gợi ý), không có thì message. Lớp 2 “Log gốc (compiler)” thu gọn, mở mới gọi getBuildLog, chữ mono, cuộn trong khung, không dịch, lỗi tải báo trong khung (EC49). Nội dung log dạng chữ thường (EC36).
  4. PDF preview (H17): build Succeeded mới nhất (latestBuild hoặc listBuilds) qua getBuildPdf; tiêu đề “Xem trước PDF · revision N”, “Trang x / n”; build mới thành công → thay PDF, giữ trang đang xem (EC50); build lỗi → giữ PDF cũ; chưa có → “Chưa có PDF” kèm hướng dẫn (EC48). Thư viện hiển thị PDF Dev chọn (H22).
  5. Export (H18): nút phụ “Export”, menu “PDF”, “Zip mã nguồn (.tex, .bib)”. PDF: không có build Succeeded → báo, zip vẫn được; build Succeeded gần nhất cũ hơn revision hiện hành → hộp “PDF thuộc revision M; revision hiện hành là N” với “Tải PDF revision M” và “Build revision N”; kiểm lại bằng header X-Build-Revision. Zip tải ngay; tên file theo Content-Disposition (EC51).
