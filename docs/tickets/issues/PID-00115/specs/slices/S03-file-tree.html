Một lát dọc làm xong và kiểm được độc lập, trong đúng luồng của ticket. Trạng thái thực hiện ghi ở report.md của Dev, không ghi ở đây. Sketch: designs/Manuscript-states.html khối 5.

Làm

  1. Cây “Tệp” từ listManuscriptFiles: thư mục suy ra từ path, file chữ mono như Manuscript.html; chọn file mở ở editor (S04) và đổi route sang đường dẫn file. Dàn ý: \section, \subsection theo thứ tự \input, \include từ file chính (Manuscript.mainFile), bỏ dòng chú thích; chọn → mở file tại dòng (H9).
  2. Thao tác (menu của mục và nút trên đầu cây, dùng được bằng bàn phím): Tạo file, Tạo thư mục, Đổi tên/di chuyển, Xóa, Tải lên. Mỗi thao tác là một commitManuscriptChanges với baseRevisionId hiện hành và Idempotency-Key; 409 xử lý như S04 (H7).
  3. Kiểm đường dẫn trước khi gửi (EC08, EC09): tương đối, không .., không bắt đầu bằng /, không \, không đoạn rỗng, không trùng file Active; lỗi viết dưới ô, nêu chưa lưu; 400 của server hiện lỗi từng trường.
  4. Nơi tham chiếu (EC10): quét nội dung các file .tex Active tìm \input{…}, \include{…} trỏ tới file (có hoặc không đuôi .tex); đổi tên, di chuyển, xóa file có nơi tham chiếu → hộp xác nhận liệt kê file:dòng trước khi gửi; sau khi xong, banner liệt kê nơi còn trỏ tên cũ, nói build sẽ báo thiếu file nếu chưa sửa, mỗi mục mở file tại dòng.
  5. Xóa (EC11): hộp xác nhận (design.md §4) nêu xóa mềm, khôi phục được từ Lịch sử; thư mục nêu số file, một revision cho cả thư mục. File đang có thay đổi chưa lưu: đổi tên, xóa vô hiệu kèm lý do (EC17).
  6. bibliography/references.bib (EC12): không đổi tên, không xóa; mở chỉ đọc với câu “System sinh từ Trusted Reference — không sửa tay”.
  7. Tải lên (EC13): uploadFile (multipart, kèm projectId) rồi commit add với fileUploadId; hình mặc định vào figures/, file khác vào thư mục đang chọn; 413 báo giới hạn, không tạo revision. Thư mục mới chưa có file chỉ ở giao diện (EC14). Mở hình → xem ảnh; nhị phân khác → “Không xem trước được” (EC15).
