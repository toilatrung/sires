Một lát dọc làm xong và kiểm được độc lập, trong đúng luồng của ticket. Trạng thái thực hiện ghi ở report.md của Dev, không ghi ở đây. Sketch: designs/Manuscript-states.html khối 6, 7.

Làm

  1. Editor theo Manuscript.html: tab các file đang mở, số dòng, tô cú pháp LaTeX, chữ mono; thư viện Dev chọn (ghi implement.md, khai gói theo H22). Nội dung lấy bằng getManuscriptFileContent; ghi nhớ hash gốc (ETag, contentHash) của mỗi file. Có hàm cho slice khác mở file tại dòng (S03, S08). Chỉ đọc khi Archived hoặc references.bib.
  2. Lưu (H6): Ctrl/Cmd+S hoặc nút “Lưu” (ghi số file chưa lưu); một commitManuscriptChanges gồm mọi file đang sửa (modify kèm content và beforeHash), baseRevisionId hiện hành, Idempotency-Key mỗi lần bấm, lưu lại sau lỗi dùng lại khóa (EC20); không có thay đổi thì không gửi (EC16). Thành công → nhãn “revision N · đã lưu HH:mm”, xóa nháp của file đã lưu. Tab file chưa lưu có dấu chấm và chữ cho trình đọc màn hình. Không tự lưu theo thời gian.
  3. Xung đột (H7): 409 base_revision_mismatch → tải lại getManuscript, listManuscriptFiles; mọi file đang lưu có contentHash trên server bằng hash gốc → tự gửi lại một lần với base mới, khóa mới (EC18); có file đã đổi → không gửi, hộp cảnh báo ở file đó nêu revision và actor đã đổi, “Xem khác biệt”, “Giữ bản của tôi” (gửi lại với base mới), “Dùng bản trên server” (xác nhận rồi bỏ thay đổi file đó) (EC19).
  4. Nháp (H8): đăng ký mỗi file đang mở với kho nháp của shell (khóa: route Manuscript của project và fileId; nội dung kèm revision gốc và hash gốc) theo README của PID-00012 S09; mở lại file có nháp khác nội dung server → banner “Có thay đổi chưa lưu từ HH:mm” với “Khôi phục”, “Bỏ nháp” (EC21); file đã đổi trên server sau thời điểm nháp → banner nói rõ (EC22). Không dùng localStorage riêng của khu vực.
  5. File đang có proposal Proposed mà có thay đổi chưa lưu → báo hộp proposal (S06) ghi “Lưu thay đổi ở file này sẽ làm proposal thành Outdated” (EC23).
  6. Sự kiện (H19): manuscript.object_status_changed loại revision → cập nhật revision hiện hành, cây file; file không có thay đổi chưa lưu và đã đổi trên server thì tải lại, có thay đổi thì giữ (EC24). Shell báo đã nối lại hoặc cần tải lại → tải lại dữ liệu khu vực, giữ thay đổi chưa lưu (EC52). Đang build vẫn sửa, lưu được (EC25).
