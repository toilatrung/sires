Bản tóm tắt theo spec-read-skill (references/brief-template.md), đã gộp câu trả lời ở mục Làm rõ của trang ticket (H1–H24, chốt theo đề xuất, PO ủy quyền 26/11/2026). Mỗi dòng dẫn nguồn: mã, đường dẫn#anchor, hoặc H1…

Làm gì

Researcher soạn bản thảo LaTeX của project trong màn Manuscript (P8): cây file, editor, vùng PDF, build log, lịch sử revision. Mọi thay đổi do Writing Agent đề xuất hiện dạng diff ngay trong editor để Researcher chấp nhận hay từ chối cả proposal (APR-05); proposal hết hiệu lực nêu lý do và cho yêu cầu tạo lại. Researcher lưu thay đổi của mình thành revision, khôi phục file về revision cũ, compile ra PDF, hiểu lỗi build qua tóm tắt bằng ngôn ngữ giao diện, export PDF hoặc zip mã nguồn. Lượt này dựng giao diện chạy trên mock ở PH-02 (D-UI, H1); hội tụ với backend thật ở cổng PH-06.

Quy tắc

  • Researcher là người duy nhất ghi trực tiếp vào file; agent chỉ tạo Change Proposal; mọi thay đổi file tạo một Manuscript Revision bất biến — PRD 12 (nguyên tắc chung); MS-EDITOR-001, MS-REVISION-001; H6
  • Lưu chủ động (Ctrl/Cmd+S hoặc nút “Lưu”), mỗi lần lưu một revision chứa mọi file đang sửa; xung đột với revision mới hơn không làm mất nội dung đang sửa; thay đổi chưa lưu được giữ cục bộ qua kho nháp của shell và đề nghị khôi phục khi mở lại — UX-STATE-004; PID-00012 H7; H6, H7, H8
  • Không sửa tay bibliography/references.bib; đường dẫn file không thoát khỏi Manuscript; đổi tên hay xóa file đang được \input, \include phải cảnh báo trước và sau; xóa là xóa mềm — MS-EDITOR-001 (AC01, AC03); H9
  • Mỗi citation key phải phân giải về một Bibliography Entry gắn Trusted Reference (KPI-02 = 100%); key không phân giải và entry của reference bị thu hồi được đánh dấu; gợi ý key từ Trusted Reference của project, chọn reference chưa có entry thì thêm vào bibliography — UX-MS-001, UX-MS-005, MS-BIB-001; H10
  • Change Proposal chỉ chấp nhận hoặc từ chối nguyên khối; chấp nhận được khi Proposed, citation check đạt (passed đúng bằng true, cùng cách DBQ-11) và không file nào của proposal có thay đổi chưa lưu; không sửa nội dung diff trước khi chấp nhận (PRD 18); Outdated không chấp nhận, không từ chối, chỉ yêu cầu tạo lại qua Orchestrator — UX-MS-002, UX-MS-003, MS-DIFF-001; H11, H12, H13
  • Build chạy cô lập ở backend; giao diện chỉ yêu cầu build revision hiện hành, theo dõi qua sự kiện; không có hủy build; build mới của revision mới hơn thay build cũ — MS-BUILD-001; PRD 18.2; H15
  • Build log hai lớp: tóm tắt lỗi bằng ngôn ngữ giao diện (dịch theo BuildIssue.code, kèm file và dòng, nhảy tới editor), log gốc mở rộng được và giữ nguyên văn — UX-MS-004; MS-BUILD-001; H16
  • PDF preview ghi revision đã build, giữ vị trí cuộn; build lỗi vẫn giữ PDF cũ; export PDF cũ hơn revision hiện hành thì báo và đề nghị build — MS-BUILD-001-AC03, MS-EXPORT-001; H17, H18
  • Lịch sử liệt kê actor, nguồn, Task; so sánh hai revision bất kỳ; khôi phục file văn bản tạo revision mới, không xóa lịch sử — UX-MS-006, MS-REVISION-001; H14
  • Project Archived chỉ đọc — PRD 7 (PROJ-CRUD-002); H20
  • Điện thoại: chỉ xem và quyết định proposal, không soạn — UX-RESP-001; H21
  • Khung: TopBar, ẩn ProjectRail, chip trạng thái, client API và SSE, kho nháp do shell cấp; thanh công cụ Manuscript thuộc PID này — PID-00012 H1, H4, H7, EC16; PC-05 P1, P2; H2, H19
  • Bất biến: agent đề xuất, System kiểm soát, Researcher quyết định; mọi phê duyệt có ngữ cảnh và hệ quả; cách ly theo tài khoản và project; nội dung diff, log, tin nhắn hiện dạng chữ thường.
