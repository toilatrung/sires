PID-00002 — Ghi chú thiết kế

Chỉ ghi điều spec mục 4 chưa nói và đã chốt khi làm rõ. Mục không có gì thì ghi “Không có”.

Dữ liệu

  • Inbox không giữ phiên bản; so phiên bản làm ở bảng replica.* bằng helper replica, không thêm bảng hay cột vào DDL (H1).
  • source_version của bảng replica lấy bằng aggregate.version của sự kiện, không dùng epoch millisecond của occurredAt nữa (H2, đóng khoảng trống ghi ở database 3.5).
  • Vai trò theo database 11.2: request dùng _app (chỉ INSERT outbox; idempotency_key có RLS); relay, consumer, helper replica, job dọn dùng _system. DBQ-01 còn mở: nếu PostgreSQL managed không cho BYPASSRLS thì vai trò _system cần thêm SET LOCAL app.scope = 'system'; không chặn PH-01 vì test chạy trên PostgreSQL cục bộ.
  • Khóa idempotency ghi ở đầu giao dịch của lệnh nên request đồng thời cùng khóa chờ nhau ở khóa chính; chỉ kết quả đã commit được lưu (theo ví dụ giao dịch F-02 ở kiến trúc 6.4).
  • Độ dài khóa kiểm theo hợp đồng (8–128); DDL cho phép tới 200 nên không xung đột.

API và sự kiện

  • event, audit bắt buộc aggregate {type, id, version}; command không bắt buộc (H2).
  • command publish tới queue cùng tên routing key qua default exchange; event, audit tới sires.events (database 9.2, AsyncAPI).
  • Thư viện tính routing key có đoạn con trạng thái đích ở một chỗ, để mọi luồng phát cùng một dạng.
  • aggregate của audit.recorded là chính Audit Event: type = audit_event, id = id Audit Event (= id dòng outbox), version = 1; luôn điền được, kể cả truy cập bị từ chối (H3, từ I2).
  • Thiếu header Idempotency-Key trả 400 validation_failed, errors[].field = Idempotency-Key, cùng dạng lỗi với bộ lọc Zod của PID-00001; 428 chỉ dành cho thiếu If-Match (H4, từ I1).
