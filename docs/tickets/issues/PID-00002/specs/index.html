4. Thiết kế kỹ thuật

4.1. Dữ liệu

Bảng ở mục 2.3, đúng DDL tham chiếu (DEC-57). Lệch thì ghi câu hỏi, không tự đổi schema.

4.2. API

Không có API mới.

4.3. Sự kiện

Phát qua outbox trong cùng giao dịch. Nghe qua inbox idempotent; bỏ bản cũ theo aggregate.version.

4.4. Quy tắc và trạng thái

  • Ghi outbox trong giao dịch, relay phát lên RabbitMQ
  • Inbox idempotent, bỏ sự kiện có aggregate.version cũ
  • Middleware Idempotency-Key dùng bảng app.idempotency_key
  • audit-emit phát audit.recorded qua outbox

4.5. Giao diện

Không có giao diện.

4.6. Agent và model

Không gọi model trực tiếp.

4.7. Lỗi và trường hợp biên

Trường hợpXử lý
Relay chết giữa chừngDòng chưa phát được phát lại khi khởi động, consumer lọc trùng qua inbox
Cùng Idempotency-Key nhưng khác bodyTừ chối theo mã lỗi ở components/responses.yaml

5. Các bước thực hiện

  1. B1 Ghi outbox trong giao dịch, relay phát lên RabbitMQ — Kết quả: Phần này hoạt động và có test hoặc lệnh kiểm — Kiểm tra: pnpm nx run @sires/platform:test
  2. B2 Inbox idempotent, bỏ sự kiện có aggregate.version cũ — Kết quả: Phần này hoạt động và có test hoặc lệnh kiểm — Kiểm tra: pnpm nx run @sires/platform:test
  3. B3 Middleware Idempotency-Key dùng bảng app.idempotency_key — Kết quả: Phần này hoạt động và có test hoặc lệnh kiểm — Kiểm tra: pnpm nx run @sires/platform:test
