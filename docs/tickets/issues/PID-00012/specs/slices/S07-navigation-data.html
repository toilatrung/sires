Một lát dọc làm xong và kiểm được độc lập, trong đúng luồng của ticket. Trạng thái thực hiện ghi ở report.md của Dev, không ghi ở đây. Làm theo H1 (PO chấp nhận phương án A của I1 ngày 18/11/2026).

ACUX-LAYOUT-001-AC01 (số Pending Actions lấy từ API)
Output specO1
Bước specB2, B5; H1
Edge caseEC23, EC24, EC33, EC34 (từ specs/scope.html)
Phụ thuộcS02, S03, S04, S05

Làm

  1. Nối interface dữ liệu của S02, S03 với client API có type (H1): số Pending Actions từ openCount của GET /pending-actions (listPendingActions); số chưa đọc từ unreadCount của GET /notifications (listNotifications); bộ chuyển ngữ cảnh liệt kê Global và các project Active (listProjects, EC34); tên project, trạng thái Plan (getProject); Active task và thao tác “Bỏ active task” (setActiveTask).
  2. Số việc chờ theo khu vực của rail: GET /pending-actions?projectId=, nhóm theo cột “Xử lý tại” của PRD 4.4 — Interactive Agent Prompt → Project AI Chat; Plan approval request, Task review request, Manual work required → Plan and Tasks; Manuscript change proposal → Manuscript; Recovery decision → Agent Activity. Reference approval xử lý ở Trusted Library (Global) nên không cộng vào khu vực nào của rail, vẫn tính trên TopBar (EC33).
  3. Cập nhật số khi có pending_action.changed, notification.created, đổi tên hay trạng thái project và Plan qua SSE của S05 (EC24). Các lần gọi lại GET sau sự kiện SSE là request chạy nền (không phải thao tác của người dùng); cách đánh dấu làm ở S13.
  4. Project không tồn tại hoặc của tài khoản khác (404) → trạng thái “không tìm thấy” (EC23).
  5. Test dùng stub của client API và SSE trong thư mục test của shell.

Kiểm

  • pnpm nx run @sires/web:test → đạt
  • apps/web/src/shell/navigation.spec.tsx › số Pending Actions từ API (UX-LAYOUT-001-AC01); › cập nhật số qua SSE (EC24); › project 404 (EC23); › nhóm số theo khu vực (EC33); › bộ chuyển chỉ có project Active (EC34)
