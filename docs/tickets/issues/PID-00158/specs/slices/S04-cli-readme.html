Làm

  1. runCli(argv, io) trả mã thoát: tham số 1 là đường dẫn module JS (tuyệt đối hoặc tính từ thư mục đang chạy), tham số 2 là tên export (mặc định stateMachines); nạp bằng import() qua pathToFileURL; mỗi phần tử là machine đã định nghĩa hoặc khai báo dạng dữ liệu cùng hình, đi lại qua defineStateMachine; ghi renderStateTransitionSql ra stdout. Lỗi (module không có, export không có, không phải mảng, khai báo sai) → stderr nêu lý do, stdout rỗng, mã 1 (EC17) — file: libs/ts/platform/src/state-machine/cli.ts (tạo mới).
  2. File chạy có shebang #!/usr/bin/env node gọi runCli(process.argv.slice(2), …) và đặt process.exitCode; thêm "bin": { "sires-state-transition-sql": "dist/state-machine/cli.js" } (hay file bin riêng Dev chọn, ghi implement.md) vào libs/ts/platform/package.json.
  3. Export từ libs/ts/platform/src/state-machine/index.ts (tạo mới) mọi tên ở spec 4.2; thêm một dòng export ở libs/ts/platform/src/index.ts (có sẵn), không đổi dòng cũ.
  4. Viết cli.spec.ts: module mẫu là file JS trong testdata (tạo mới, xuất stateMachines là dữ liệu đọc từ golden-machines.json); “in SQL” (stdout bằng golden.txt sau khi bỏ \r, mã 0); “lỗi module” (đường dẫn không có, export không có, export không phải mảng: mã 1, stderr có lý do, stdout rỗng) — file: libs/ts/platform/src/state-machine/cli.spec.ts (tạo mới).
  5. Cập nhật libs/ts/platform/README.md (có sẵn): API (bảng spec 4.2); quy trình dùng trong migration và đổi khai báo về sau theo spec 4.4 (EC18), có ví dụ lệnh pnpm nx run @sires/<service>:build rồi pnpm exec sires-state-transition-sql dist/…/state-machines.js trong thư mục service; nhắc chạy node scripts/docs/add-license.mjs cho file .sql mới; ví dụ test so dòng sau migration bằng compareStateTransitionRows.
