Bản tóm tắt theo spec-read-skill, đã gộp câu trả lời ở mục Làm rõ của trang ticket (H1–H4). Mỗi dòng dẫn nguồn.

Làm gì

Luồng platform (người làm T1xNTH) viết một helper TypeScript trong libs/ts/platform và bản Python tương đương trong libs/py/sires_common. Service khai báo state machine của mình một lần, dạng dữ liệu, trong module domain; từ khai báo đó helper kiểm chuyển trạng thái ở domain và sinh SQL nạp bảng app.state_transition để dán vào migration của service. Tám PID migration của PH-01 dùng helper để database có đúng 133 cặp của DDL mà không chép tay (D2, DEC-57). Helper không chứa machine của service nào.

Quy tắc

  • Bảng app.state_transition là bản sinh từ khai báo state machine trong module domain, không viết tay — DEC-57, DBQ-09, database 10.2.
  • Sinh cả hàm kiểm ở domain và dòng ở database từ một khai báo; test so khớp trong CI — DR-01; H2.
  • TS ở libs/ts/platform, Python tương đương ở libs/py/sires_common; SQL sinh ra vào migration của service; PID migration khai báo, PID tính năng dùng lại — H1 (D2).
  • Khai báo gồm mã, từ, đến, actor; có hàm kiểm chuyển và hàm sinh SQL; service chạy script sinh SQL vào một migration; không đổi DDL — H2 (PID-00023 I2).
  • Migration là văn bản SQL cố định (custom migration drizzle-kit chạy bằng migrate(); Alembic trên asyncpg); chỉ tiến; đổi khai báo về sau là migration mới — H4 (D1); database 12.4.
  • Knowledge khai báo indexing_job dạng dữ liệu trong mã domain, sinh SQL vào revision Alembic — H3 (PID-00026 I1).
  • Trạng thái và chuyển trạng thái: helper chỉ kiểm cặp (từ, đến); cặp ngoài khai báo, kể cả X → X, bị từ chối với invalid_transition — PRD 18.2, DATA-STATE-001; guard, chọn đích, quyền theo trạng thái, APR ở module domain của service — database 10.2.
  • Domain logic kiểm thử được không cần mạng — NFR-MAINT-004. Thư viện chỉ đổi tương thích ngược — quy tắc 1.4.5.
  • Bất biến: agent đề xuất, System kiểm soát, Researcher quyết định — helper không thay đổi; actor kèm cặp chỉ là dữ liệu cho module domain.

Thuật ngữ

  • machine = state machine của một entity (cột trạng thái), tên theo cột machine của app.state_transition (task, plan_version, workflow…)
  • cặp, chuyển trạng thái = transition (từ from_state → đến to_state), PRD 18.2
  • mã = code: mã PRD của chuyển trạng thái khi có (T-01–T-19, APR-01)
  • actor = ActorRef.type: Researcher → researcher, agent → agent, System → system (PRD 1.5)
  • SQL đồng bộ = câu DELETE cặp không còn khai báo cộng câu INSERT … ON CONFLICT cập nhật mã
