1. Ticket

  • Mục đích: DEC-57 bắt bảng app.state_transition của mỗi database là bản sinh từ khai báo state machine trong module domain, không viết tay (DBQ-09, DR-01). Tám PID migration của PH-01 (8 service, 25 machine, 133 cặp trạng thái) cần cùng một công cụ: khai báo dạng dữ liệu, một hàm kiểm chuyển dùng chung cho domain, SQL sinh ra xác định để đặt vào migration, và cách so dòng trong database với khai báo. Một helper ở luồng platform tránh tám cách làm khác nhau.
  • Gồm: TypeScript ở libs/ts/platform: kiểu khai báo machine (tên, trạng thái, cặp từ → đến kèm mã và actor tùy chọn) và hàm định nghĩa có kiểm khai báo; hàm kiểm chuyển với lỗi miền mang mã invalid_transition; hàm sinh dòng và SQL xác định dạng đồng bộ (chỉ chạm các machine truyền vào); hàm so dòng đọc từ database với khai báo; lệnh in SQL sires-state-transition-sql. Python ở libs/py/sires_common: module sires_common.state_machine tương đương, SQL giống từng byte bản TS, lệnh python -m sires_common.state_machine. Test đối chiếu mọi khối INSERT INTO app.state_transition của docs/database/ddl trên PostgreSQL 16. README hai thư viện.
  • Không gồm: khai báo machine của từng service, migration nạp dòng và test so dòng sau migration (8 PID migration, D2); guard, chọn đích, quyền theo trạng thái, APR, Audit Event (module domain của service, PID tính năng); ánh xạ lỗi sang HTTP 409 (service); sinh CHECK và trigger (giữ SQL chép từ DDL theo D1); thêm gói vào pnpm catalog (luồng infra).

Chi tiết phạm vi và edge case: specs/scope.html.

Đầu vào

  • PID phải xong trước: không có. startPostgres() của @sires/testing (PID-00004) và fixture sires_postgres của sires_common.testing (PID-00005) đã có trên main.
  • Dữ liệu: bảng app.state_transition ở docs/database/ddl/00-common.sql; khối INSERT INTO app.state_transition của 8 file DDL service (bảng ở spec 2.3).

Đầu ra

  • Mã TS: libs/ts/platform/src/state-machine/ (tạo mới) — khai báo, kiểm chuyển, sinh SQL, so dòng, lệnh in SQL; export ở libs/ts/platform/src/index.ts; bin trong libs/ts/platform/package.json
  • Mã Python: libs/py/sires_common/src/sires_common/state_machine.py (tạo mới)
  • Bộ mẫu dùng chung: libs/ts/platform/src/state-machine/testdata/golden-machines.json, golden.txt (tạo mới)
  • Test: libs/ts/platform/src/state-machine/*.spec.ts; libs/py/sires_common/tests/test_state_machine*.py (tạo mới)
  • Tài liệu: libs/ts/platform/README.md, libs/py/sires_common/README.md — API và quy trình dùng trong migration

2. Tiêu chí nghiệm thu

  • PID-00158-AC01 Given một machine khai báo bằng helper (tên, danh sách trạng thái, các cặp từ → đến kèm mã và actor tùy chọn), When kiểm một cặp bằng hàm kiểm chuyển của TS hoặc của Python, Then cặp có trong khai báo được nhận và trả về kèm mã; mọi cặp khác, kể cả cặp cùng trạng thái, bị từ chối bằng lỗi mang mã invalid_transition, tên machine và trạng thái hiện hành.
  • PID-00158-AC02 Given khai báo sai — tên machine không đúng dạng snake_case, danh sách trạng thái hay danh sách cặp rỗng, trạng thái trùng, cặp trùng, cặp từ một trạng thái về chính nó, trạng thái không có trong danh sách, giá trị rỗng, có ký tự điều khiển hay khoảng trắng ở đầu, cuối — When định nghĩa machine, Then helper báo lỗi ngay lúc định nghĩa, nêu machine và giá trị sai; không có đối tượng machine nào được tạo.
  • PID-00158-AC03 Given cùng một tập machine, When sinh SQL nhiều lần, hoặc sau khi đổi thứ tự machine, thứ tự trạng thái, thứ tự cặp, Then chuỗi SQL giống hệt nhau; Given bộ khai báo mẫu dùng chung golden-machines.json, When sinh SQL bằng TS và bằng Python, Then cả hai bằng đúng từng byte nội dung golden.txt.
  • PID-00158-AC04 Given dòng của mọi khối INSERT INTO app.state_transition trong docs/database/ddl (8 file, 25 machine, 133 cặp ngày 18/11/2026), When khai báo lại bằng helper rồi chạy SQL sinh ra trên PostgreSQL 16 có bảng app.state_transition của 00-common.sql, Then tập dòng (machine, from_state, to_state, code) bằng đúng tập dòng mà khối INSERT của DDL tạo ra; chạy SQL lần hai không đổi dòng nào.
  • PID-00158-AC05 Given bảng có dòng lệch khai báo của một machine (thiếu cặp, thừa cặp, khác mã) và dòng của một machine khác, When chạy SQL sinh cho machine đó, Then dòng của machine đó bằng khai báo và dòng của machine kia giữ nguyên; Given dòng đọc từ database, When so bằng hàm so dòng, Then hàm trả đúng từng cặp thiếu, thừa, khác mã, và trả rỗng khi khớp.
  • PID-00158-AC06 Given một module xuất danh sách machine (TS: export stateMachines của file JS đã build; Python: thuộc tính STATE_MACHINES), When chạy lệnh in SQL, Then stdout bằng đúng chuỗi của hàm sinh SQL và mã thoát 0; module không có, tên xuất không có, hay giá trị không phải danh sách machine hợp lệ thì mã thoát khác 0, thông báo ở stderr, stdout rỗng.
  • AC requirement: không phủ trực tiếp. Helper là phương tiện để các PID migration phủ DATA-STATE-001-AC01 (lớp database) và NFR-MAINT-003-AC01 theo DEC-57.

Bảng AC → test → slice: specs/acceptance.html.
