Một lát dọc làm xong và kiểm được độc lập, trong đúng luồng của ticket. Trạng thái thực hiện ghi ở report.md của Dev, không ghi ở đây.

ACKhông có AC riêng (spec B3, O2, O3)
Output specO2, O3

Edge caseKhông có
Phụ thuộc—

Làm

  1. Dựng khung module của manuscript trong apps/manuscript/src/ và gắn vào apps/manuscript/src/app.module.ts (có sẵn). Chia module là quyết định kỹ thuật của Dev (tickets 1.6 không liệt kê manuscript); gợi ý theo đường dẫn Module của PID sau: revisions/ (PID-00053), proposals/ (PID-00079), bibliography/ (PID-00095), builds/ (PID-00108), kpi/ (PID-00146). Ghi cách chia ở implement.md.
  2. Cập nhật apps/manuscript/src/app.module.spec.ts (có sẵn): service vẫn khởi động, /health trả { service: 'manuscript', status: 'ok' }, các module khung được nạp.
  3. Sửa apps/manuscript/README.md (có sẵn): dòng “Bản sao chỉ đọc” liệt kê replica.project_state (từ project.lifecycle_changed, chặn ghi khi project Archived hoặc đã xóa mềm) và replica.reference_state (từ reference.status_changed, reference.metadata_updated, reference.deleted; BibliographyEntry chỉ từ Reference Trusted, báo needs review khi metadata đổi) — database 3.4; thêm mục chạy migration; liệt kê module.

Kiểm

  • pnpm nx run @sires/manuscript:test → đạt
  • Test: apps/manuscript/src/app.module.spec.ts › nạp module khung (spec B3)
  • pnpm nx run @sires/manuscript:build, :typecheck, :lint → đạt
  • Đọc lại apps/manuscript/README.md (spec O3)

Xong khi

  • Service khởi động với khung module, test đạt, README ghi đúng entity sở hữu, hai bảng sao chỉ đọc và sự kiện nguồn.
