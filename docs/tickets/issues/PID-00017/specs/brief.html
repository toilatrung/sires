Làm gì

System (không có tác nhân người dùng): dựng database sires_workspace bằng migration của chính service, đúng DDL tham chiếu, kèm test chứng minh schema khớp và các ràng buộc của DDL hoạt động; dựng khung để PID-00044 trở đi viết nghiệp vụ project, chat, Pending Action, Notification mà không phải tự dựng lại cấu hình, kết nối database, lệnh migrate và kiểm token nội bộ.

Quy tắc

  • DDL tham chiếu là chuẩn; migration phải sinh ra cùng schema; CI dựng database từ migration và từ ddl/ rồi so — DBD-02, database 12.4
  • Migration chỉ tiến, nằm trong thư mục service, chỉ chạm database của service; lệch DDL thì ghi DBQ, không tự đổi schema — quy tắc 1.4.6
  • Migration đầu là SQL chép từ 00-common.sql rồi workspace.sql, đặt làm custom migration SQL của drizzle-kit (có journal), chạy bằng migrate() của drizzle-orm trong mã service; chỉ tiến; schema TypeScript của Drizzle do PID tính năng viết — kiến trúc 2.3, kiến trúc 6.10; H1
  • PID migration gồm test hành vi DDL, lệnh migrate riêng của service và giá trị Helm migration.enabled, migration.command — H5; drizzle-kit, drizzle-orm vào pnpm catalog qua PID-00001 — H6
  • Bốn vai trò mỗi database (sires_workspace_owner, _app, _system, _purge) do hạ tầng tạo, migration không tạo; _app chịu RLS, _system và _purge BYPASSRLS — database 3.2, DBD-06; cục bộ: compose tạo ở PID-00159, tới lúc đó test tự tạo — H4
  • Workspace không cấp DELETE cho _app trên bảng nào; research_context_version, message bất biến (trigger + thu UPDATE) — docs/database/ddl/workspace.sql
  • Trạng thái và chuyển trạng thái: ResearchProject Active ↔ Archived; PendingAction Open → Resolved, Open → Expired, Expired → Resolved; Notification Unread → Read. Xóa mềm và khôi phục project không đổi status (cột deleted_at, purge_after = deleted_at + 30 ngày, status_before_deletion) — PRD 18.2, database 10.2
  • State machine khai báo một lần trong module domain; bảng app.state_transition sinh từ khai báo bởi migration, không viết tay; trigger là lớp thứ hai — DEC-57, DBQ-09, NFR-MAINT-003. PID này khai báo ba machine dạng dữ liệu (chỉ 6 cặp, không điều kiện) và sinh dòng bằng helper của PID-00158 vào một custom migration; PID-00044, PID-00064 dùng lại khai báo và thêm điều kiện — H2, H3
  • Token nội bộ ES256, kid = tên service, hạn ≤ 5 phút; thiếu hoặc sai token → 401 invalid_service_token; service ngoài x-callers → 403 caller_not_allowed — internal/schemas.yaml#/ServiceTokenClaims, internal/responses.yaml, PID-00003
  • Lỗi trả về chỉ dùng ErrorCode, FieldErrorCode (components/schemas/common.yaml); PID này không có endpoint nghiệp vụ nên chỉ gặp mã của guard.
  • Bất biến của SIRes giữ nguyên: agent đề xuất, System kiểm soát, Researcher quyết định; cách ly theo tài khoản (RLS) và project.
