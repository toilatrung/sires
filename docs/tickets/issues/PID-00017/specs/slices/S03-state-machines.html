Làm

  1. Khai báo ba machine dạng dữ liệu trong module domain (tạo mới, ví dụ apps/workspace/src/domain/state-machines.ts) theo kiểu khai báo của PID-00158 (H2, H3): research_project Active → Archived, Archived → Active; pending_action Open → Resolved, Open → Expired, Expired → Resolved; notification Unread → Read. Chỉ cặp, không thêm điều kiện (để PID-00044, PID-00064, các PID đó dùng lại khai báo này).
  2. Hàm kiểm chuyển (dùng hàm chung của PID-00158 trên khai báo này): cặp ngoài khai báo (kể cả cùng trạng thái) bị từ chối với mã invalid_transition và trạng thái hiện hành (ErrorCode, Problem.currentState).
  3. Sinh SQL nạp dòng app.state_transition của ba machine từ khai báo bằng helper của PID-00158 (hàm sinh SQL hoặc lệnh in SQL của PID đó, đọc danh sách machine mà module domain xuất) và đặt vào một custom migration SQL mới của drizzle-kit, sau migration đầu của S01 (H1, H2); không chép tay, không sửa tay file sinh ra. Cách gọi (script trong package.json hay lệnh khác) Dev chọn, ghi README và implement.md.
  4. Test domain: mọi cặp có thứ tự của từng machine. Test database: sau migration, bảng bằng khai báo (dùng hàm so dòng của PID-00158) và bằng dòng của DDL tham chiếu; trigger từ chối cặp ngoài bảng và nhận cặp trong bảng.
