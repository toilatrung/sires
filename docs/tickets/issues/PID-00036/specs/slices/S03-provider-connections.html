Một lát dọc làm xong và kiểm được độc lập, trong đúng luồng của ticket. Trạng thái thực hiện ghi ở report.md của Dev, không ghi ở đây. Theo H5–H8 (chốt theo đề xuất, PO ủy quyền 26/11/2026). Phần thiết kế chưa vẽ (cột hành động, thông báo kết nối đầu tiên, Invalid trong form) dựng theo design.md §4 và sketch designs/Settings-states.html (Phải sửa ở nguồn mục 7).

Làm

  1. View /settings/providers theo SettingsProviders: câu “Bạn tự cung cấp API key…”, nút “Thêm kết nối”, bảng cột Tên, Provider, Base URL, API key (•••••••• + keyHint), Kiểm tra (chip testStatus kèm giờ lastTestedAt theo design.md §6 hoặc mã lastError.code), Agent dùng (assignedAgents, default ghi “Mặc định”), cột hành động: “Sửa”, “Kiểm tra lại”, “Xóa” (S04). Dữ liệu từ listProviderConnections. Văn bản người dùng nhập hiển thị dạng chữ (EC54).
  2. Trống: “Thêm API key của bạn để agent hoạt động” kèm “Thêm kết nối” (UX-SETTINGS-002-AC02 phần Settings, EC13).
  3. Form “Kết nối mới” (và “Sửa kết nối”): Tên (1–100), Provider (đúng ba lựa chọn Anthropic Claude, OpenAI, Google Gemini → anthropic, openai, google), Base URL điền sẵn https://api.anthropic.com, https://api.openai.com/v1, https://generativelanguage.googleapis.com kèm ghi chú tương thích API chính thức; đổi provider khi base URL chưa sửa thì đổi theo (EC14); kiểm https:// và URL hợp lệ (EC15); không cảnh báo base URL proxy (EC16). API key type="password", autocomplete="off", ít nhất 8 ký tự (EC18), không nút hiện key.
  4. Tài khoản chưa có kết nối: form có khối thông báo NFR-PRIV-001 và ô “Tôi đã đọc”; “Kiểm tra kết nối” vô hiệu tới khi đánh dấu (NFR-PRIV-001-AC01, EC13).
  5. “Kiểm tra kết nối”: lần đầu createProviderConnection rồi testProviderConnection; đã tạo mà sửa key hoặc base URL thì updateProviderConnection rồi kiểm; ô key trống khi sửa thì không gửi apiKey (EC23). Trong lúc chạy: nút “Đang kiểm tra…” vô hiệu, dòng role="status" (EC21). 409 duplicate_name → lỗi ô tên (EC17); 400 → lỗi từng trường (EC18); lỗi của chính lệnh (5xx, mạng) → lỗi UX-STATE-003, trạng thái giữ (EC21).
  6. Kết quả trong form: Valid → chip và số model (availableModels; rỗng thì “Không lấy được danh sách model”, EC24); Invalid → chip, mã, câu của SIRes và một nút theo bảng H6: “Sửa API key” (focus ô key), “Sửa base URL”, hoặc “Kiểm tra lại” (PID-00036-AC01, EC19, EC20). Không hiển thị lastError.message.
  7. “Lưu” bật khi Valid, đóng form và làm mới bảng; đóng form khi Untested hoặc Invalid thì kết nối ở lại bảng (EC22). “Kiểm tra lại” ở bảng gọi testProviderConnection.
  8. Key: giữ trong state của form tới khi lệnh tạo hoặc sửa trả về rồi xóa; không đưa vào URL, log, localStorage, sessionStorage, kho nháp của shell, thông báo lỗi; form này không đăng ký với kho nháp (EC25, H7).
  9. Kịch bản mock cho test: key sai → Invalid auth_failed; lỗi tạm thời; tên trùng; danh sách rỗng; proxy Valid.
