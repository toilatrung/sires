Bản tóm tắt theo spec-read-skill, gộp yêu cầu PO 12/11/2026, 16/11/2026 đã có trong ticket và spec. Làm rõ 17/11/2026 theo lô PH-01; ngày 18/11/2026 PO chấp nhận đề xuất của cả chín phiếu, đã gộp thành H1–H10 (trang ticket, mục 5). Không còn điểm chưa chốt; phiếu I1–I9 ở others/issues.html giữ làm biên bản. Mỗi dòng dẫn nguồn.

Làm gì

Tác nhân là System (GitHub Actions trên runner của GitHub). Mỗi pull request và mỗi push vào main chạy CI: kiểm thay đổi trước, rồi chạy đúng các job cần cho thay đổi đó (PR vào develop) hoặc mọi job (PR vào main, push vào main). CI có thêm contract test, kiểm payload theo AsyncAPI, Redocly lint, quét secret và phụ thuộc, build image, cache Nx, và ghi thời gian từng job. Mục tiêu cổng PH-01: PR chạm một service NestJS xong CI dưới 10 phút.

Quy tắc

  • Job đầu tiên tính thay đổi so với merge-base của nhánh đích: project Nx bị ảnh hưởng và nhóm thay đổi (TS, Python, hợp đồng docs/api-design, tài liệu, Dockerfile/Helm/Terraform, workflow và file dùng chung); job khác đọc kết quả này — spec 4.4; kiến trúc 11.3 (PO 12/11/2026)
  • PR vào develop: job không liên quan bỏ qua bằng if: ở mức job (skipped được tính là đạt); không lọc bằng paths ở mức workflow vì check bắt buộc sẽ treo “Expected” — spec 4.4, 4.7
  • PR vào main và push vào main: mọi job, mọi project, vẫn dùng Nx cache — spec 4.4; AC06
  • Tới khi PID-00035 xong, mọi PR tính năng vẫn vào main nên thực tế chạy toàn bộ; chế độ lọc chỉ kiểm được bằng PR thử vào develop — OQ-111
  • Không tính được thay đổi (job lỗi, thiếu merge-base, clone nông) hoặc sửa file dùng chung → chạy toàn bộ — spec 4.7
  • tracks và build là check bắt buộc của ruleset protect-main-develop: giữ hai tên này; build thành job tổng chờ mọi job, đạt khi mọi job đạt hoặc skipped — spec 4.7; AGENT.md mục Git
  • Hủy lần chạy cũ khi PR có push mới; không hủy lần chạy của push vào main; cache pnpm, uv, Nx, layer Docker; job độc lập chạy song song; mỗi job có timeout-minutes; thời gian từng job trong job summary — spec 4.4, B9; AC07, AC08
  • Ngưỡng ngoài AC01 (PR không chạm code, lần chạy toàn bộ trên main) = p95 của 20 lần chạy gần nhất cộng 20%; Dev ghi số đo vào report.md, PO thêm thành AC — OQ-112. PID xong khi AC01–AC08 đạt: report.md có số đo đã có, số lần chạy mỗi loại và lệnh tính p95 cộng 20% (lệnh ở lại repo); khi đủ 20 lần (loại có lọc: sau PID-00035) PO hoặc Dev chạy lại lệnh, PO thêm AC, không mở lại PID này — H5
  • AC01 (dưới 10 phút) kết luận bằng lần chạy thường: PR mới vào develop có cache của main; lần không cache ghi để tham khảo — H4
  • Contract test bằng Schemathesis cho OpenAPI nội bộ của service bị ảnh hưởng, kiểm payload theo AsyncAPI — kiến trúc 11.3; ADR-14. Mỗi project tự tham gia bằng target Nx của mình (một cho Schemathesis, một cho kiểm payload) khi đã có operation hay sự kiện; PID này làm runner, bộ kiểm dùng chung, job chạy target cho project bị ảnh hưởng (chế độ toàn bộ: mọi project có target) và bộ tự kiểm trong thư mục infra; hôm nay chưa project nào có target nên job chỉ chạy bộ tự kiểm — H2
  • Quét phụ thuộc thất bại khi có lỗ hổng High hoặc Critical đã có phiên bản sửa; mức khác và lỗ hổng chưa có bản sửa ghi vào job summary; ngoại lệ khai trong file cấu hình của luồng infra kèm lý do, PO xem khi review PR — H3
  • Kiểm chart Helm bằng check-charts.mjs (PID-00010) khi chart chung hoặc apps/<service>/deploy/values.yaml đổi; terraform fmt -check, validate khi infra/terraform đổi; chế độ toàn bộ chạy cả hai — H6
  • Redocly lint khi sửa spec bằng ba lệnh ở docs/api-design/README.md (@redocly/cli@2.11.1) — kiến trúc 11.3; spec B3. Cùng job bundle OpenAPI ra thư mục tạm bằng cùng phiên bản Redocly và so với docs/api-design/dist/openapi.bundled.yaml (bỏ qua khác biệt ký tự xuống dòng); lệch thì thất bại và in lệnh bundle — H9
  • Build image cho service bị ảnh hưởng; đẩy image lên registry thuộc pipeline deploy khi merge vào develop — kiến trúc 11.3; ticket “Không gồm” PID-00035
  • Nx affected và remote cache là công cụ đã chốt — ADR-21. Cache Nx trong CI chỉ dùng cache của GitHub Actions: không dịch vụ ngoài, không tài khoản hay secret, nx.json giữ neverConnectToCloud, PR không ghi vào cache của main — H1
  • Cài phụ thuộc Python trong CI bằng uv sync --all-packages --locked (lock lệch thì thất bại, như pnpm install --frozen-lockfile) — H7

  • Một PR một luồng: PID này chỉ sửa thư mục của luồng infra (.github/workflows/, scripts/development/, infra/, file cấu hình gốc); không sửa project.json, package.json của luồng khác — quy tắc 1.4.1, mục 1.3

Thuật ngữ

  • Chế độ lọc = PR vào develop, chỉ chạy job liên quan tới thay đổi; chế độ toàn bộ = PR vào main, push vào main, và mọi trường hợp không tính được thay đổi
  • Nhóm thay đổi = loại file bị sửa (TS, Python, hợp đồng, tài liệu, Dockerfile/Helm/Terraform, workflow và file dùng chung), do job kiểm thay đổi xuất ra
  • Job tổng build = job cuối chờ mọi job, là check bắt buộc của ruleset
  • PR thử = pull request chỉ để kiểm CI, không merge, đóng và xóa nhánh sau khi kiểm
  • Bộ tự kiểm = service nhỏ trả đúng và sai schema, payload đúng và sai, đặt trong thư mục luồng infra, để kiểm runner contract test và bộ kiểm payload khi chưa service nào tham gia (H2)
  • Target tham gia = target Nx do project tự khai trong thư mục của mình để job contract test, kiểm payload chạy (H2); tên và cách khai theo README của runner
