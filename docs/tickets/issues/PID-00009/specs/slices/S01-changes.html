Một lát dọc làm xong và kiểm được độc lập, trong đúng luồng của ticket. Trạng thái thực hiện ghi ở report.md của Dev, không ghi ở đây. Các slice sau thêm job vào khung này.

Phụ thuộc—

Làm

  1. Viết script kiểm thay đổi trong thư mục của luồng infra (tạo mới, ví dụ scripts/development/ci-changes.mjs; Dev chọn tên, ghi implement.md): so HEAD với merge-base của nhánh đích; xuất chế độ, danh sách project Nx bị ảnh hưởng, các nhóm thay đổi (TS, Python, hợp đồng, tài liệu, Dockerfile/Helm/Terraform, workflow và file dùng chung). Nên nhận danh sách file qua stdin như check-tracks.mjs --stdin để kiểm EC không cần PR.
  2. Quy tắc chế độ: lọc chỉ khi sự kiện là pull_request vào develop và tính được thay đổi; toàn bộ với PR vào main, push vào main, nhánh đích khác (EC10), không tính được thay đổi (EC07), có file dùng chung (EC04). Nhóm hợp đồng kéo theo @sires/contracts và project phụ thuộc (EC08). Nhóm Dockerfile/Helm/Terraform xuất thêm cờ “chart đổi” (chart chung infra/helm/sires-service/ hoặc apps/<service>/deploy/values.yaml) và “Terraform đổi” (infra/terraform/) để S11, S12 đọc (EC15, H6).
  3. Trong .github/workflows/ci.yml (có sẵn): job đầu tiên chạy script, checkout fetch-depth: 0, đưa kết quả ra outputs; job khác needs job này và dùng if: ở mức job. Không thêm paths, paths-ignore ở mức workflow (EC02).
  4. Tách job tài liệu: node scripts/docs/add-license.mjs --check, node scripts/docs/update-index.mjs --check trên checkout sạch, chạy mọi lần, không khôi phục cache công cụ Python (EC09).
  5. Job TS (lint, typecheck, test, build cho project lang:ts) và job Python (lint, typecheck, test cho project lang:python): chế độ lọc dùng nx affected trên project bị ảnh hưởng và skipped khi nhóm không đổi; chế độ toàn bộ dùng nx run-many cho mọi project. Job Python cài bằng uv sync --all-packages --locked (bỏ ghi chú “Switch to --frozen…” trong ci.yml); lock lệch thì thất bại (EC21, H7).
  6. Sửa scripts/development/check-tracks.mjs (có sẵn, luồng infra): pnpm-lock.yaml, uv.lock không còn ánh xạ vào luồng infra mà không tính là luồng, như docs, repo; các file gốc khác giữ nguyên. Script kiểm thay đổi vẫn coi lock file là file dùng chung (EC04, EC22, H8).
  7. Giữ job tracks như hiện có. Đổi job build hiện có thành job tổng: needs mọi job, if: always(), đạt khi mọi job đạt hoặc skipped, thất bại khi có job thất bại hoặc bị hủy (EC03). Hai tên tracks, build không đổi.
  8. Ghi trong README của thư mục chứa script (hoặc infra/README.md) cách chạy script cục bộ và bảng nhóm → job.

Kiểm

  • node scripts/development/check-tracks.mjs → chỉ luồng infra
  • node scripts/docs/add-license.mjs --check → đạt (file mới có ghi chú giấy phép)
  • Script kiểm thay đổi với danh sách file: agent/execution/PID-00009/report.md → chế độ lọc, không project, nhóm tài liệu; uv.lock → toàn bộ (EC04); docs/api-design/internal/schemas.yaml → nhóm hợp đồng, có @sires/contracts (EC08); infra/helm/sires-service/values.yaml → nhóm Dockerfile/Helm/Terraform (EC15); nhánh đích không tồn tại → toàn bộ (EC07); nhánh đích khác main, develop → toàn bộ (EC10)
  • check-tracks.mjs --stdin với hai dòng apps/gateway/package.json, pnpm-lock.yaml → chỉ luồng gateway; với infra/helm/sires-service/values.yaml → luồng infra (EC22)
  • Thao tác tay trên nhánh thử (EC21): thêm phụ thuộc vào pyproject.toml của một project mà không chạy uv lock → job Python thất bại ở bước uv sync --locked; hoàn lại
  • Thao tác tay trước PR thử: git rev-list --count origin/develop..origin/main = 0 (EC11)
  • PR thử T1 vào develop (PID-00009-AC04; EC02, EC03)
  • T4 — CI của PR PID-00009 vào main: chế độ toàn bộ, mọi job chạy (PID-00009-AC06, phần chạy toàn bộ)

Xong khi
