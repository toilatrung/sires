Một lát dọc làm xong và kiểm được độc lập, trong đúng luồng của ticket. Trạng thái thực hiện ghi ở report.md của Dev, không ghi ở đây. DEC-57 (DBQ-09) và DR-01 yêu cầu bảng app.state_transition sinh từ khai báo state machine, không viết tay. Theo H3 (phiếu I3 phương án B, quyết định chung D2): helper chung ở PID-00158 (libs/ts/platform) sinh dòng từ state machine khai báo dạng dữ liệu; slice này khai báo bốn machine của library và sinh dòng bằng helper đó.

Làm

  1. Khai báo dạng dữ liệu, theo định dạng của helper PID-00158, trong mã domain của library (apps/library/src/; file và module đặt khai báo do Dev chọn, ghi implement.md; PID tính năng dùng lại khai báo này), bốn machine đúng các cặp from → to trong docs/database/ddl/library.sql: discovered_result (New → Selected, New → Rejected, Selected → New, Selected → Imported), reference_approval (Pending Approval → Trusted, Pending Approval → Rejected, Trusted → Revoked, Revoked → Trusted), reference_indexing (Not Indexed → Queued, Not Indexed → Unavailable, Queued → Indexing, Indexing → Indexed, Indexing → Failed, Failed → Queued, Unavailable → Queued, Indexed → Queued), project_reference_selection (Active → Removed, Removed → Active).
  2. Sinh câu SQL chèn dòng app.state_transition từ khai báo bằng helper của PID-00158 và đặt vào migration của service: cùng custom migration SQL của S01 nếu S01 chưa merge, hoặc một custom migration SQL mới của drizzle-kit nếu S01 đã merge (chỉ tiến — H5). Không chép tay dòng INSERT từ DDL; không viết bộ sinh riêng trong service.
  3. Test apps/library/src/db/state-transition.spec.ts (tạo mới): dòng trong database khớp khai báo và khớp DDL tham chiếu; thử mọi cặp trạng thái của từng machine bằng UPDATE — chỉ cặp trong bảng được chấp nhận (EC10).
