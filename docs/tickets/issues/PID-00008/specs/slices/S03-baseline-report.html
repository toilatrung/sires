S03 — Danh sách kiểm baseline và báo cáo

Nội dung

  • Kiểm

Một lát dọc làm xong và kiểm được độc lập, trong đúng luồng của ticket. Trạng thái thực hiện ghi ở report.md của Dev, không ghi ở đây. Slice này chỉ đọc docs/api-design; mọi sai lệch tìm thấy được ghi vào báo cáo, không sửa.

ACPID-00008-AC02
Output specO1 (lệnh dùng để kiểm); báo cáo ở spec mục 6
Bước specB2
Edge caseEC08, EC09 (từ specs/scope.html)
Phụ thuộcS01, S02 (H1); PID-00007 đã merge 18/11/2026 (PR #33); lúc làm rõ chưa làm: ghi nhận, không chặn (H4)

Làm

  1. Trên main mới nhất, chạy pnpm nx run @sires/contracts:generate (TS công khai, nội bộ, AsyncAPI; client và mô hình Python), pnpm nx run @sires/contracts:typecheck, pnpm nx run @sires/contracts:check-drift; ghi commit đã kiểm và kết quả từng lệnh.
  2. Kiểm và ghi bằng chứng file:dòng cho từng mục: DBQ-03 — message usage.recorded có trong events/asyncapi.yaml, x-producer: knowledge, x-consumers có orchestration; DBQ-04 — EventEnvelope.required có aggregate, aggregate.required = type, id, version (internal/schemas.yaml), reference.status_changed có metadataVersion bắt buộc; type TS và mô hình Python sinh ra có đúng các trường đó (tên type, file sinh).
  3. Gộp lại docs/api-design/openapi.yaml vào thư mục tạm bằng lệnh ở docs/api-design/README.md (npx @redocly/cli@2.11.1 bundle …) và so với dist/openapi.bundled.yaml; lệch thì ghi là việc của PO (EC09).
  4. Ghi mâu thuẫn hợp đồng còn mở: routing key (trang ticket, mục “Phải sửa ở nguồn”) và mọi mâu thuẫn mới thấy, mỗi mục trích đúng hai đoạn (EC08).
  5. Viết mục “Baseline hợp đồng” trong agent/execution/PID-00008/report.md: phiên bản info.version của từng file hợp đồng, commit đã kiểm, bảng mục kiểm (đạt/không, bằng chứng), kết quả lệnh, mâu thuẫn còn mở, kết luận “Baseline sẵn sàng cho PO duyệt”, hoặc “Chưa sẵn sàng” kèm tên mục chưa đạt. Không tự ghi “PO đã duyệt”.

Kiểm

Xong khi
