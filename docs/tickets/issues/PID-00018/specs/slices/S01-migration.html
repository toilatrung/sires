Phụ thuộcPID-00001 (drizzle-kit, drizzle-orm trong pnpm catalog — H4; chưa merge, ghi nhận không chặn Sẵn sàng). pg, @sires/testing đã có. Cách viết migration đã chốt (H1).

Làm

  1. Theo H1: thêm drizzle-kit (dev) và drizzle-orm vào apps/audit/package.json bằng catalog:; cấu hình drizzle-kit (tạo mới, ví dụ apps/audit/drizzle.config.ts, dialect PostgreSQL, thư mục ra migrations/); tạo migration đầu rỗng bằng drizzle-kit generate --custom trong apps/audit/migrations/ (xoá .gitkeep; giữ journal của drizzle-kit), rồi chép vào đó docs/database/ddl/00-common.sql rồi docs/database/ddl/audit.sql; không đổi schema, không tạo vai trò, không viết schema TypeScript của Drizzle cho bảng; giữ license ở đầu file.
  2. Viết hàm chạy migration dùng chung (tạo mới, ví dụ apps/audit/src/db/migrate.ts) bằng migrate() của drizzle-orm (node-postgres): áp mọi migration chưa chạy trong giao dịch, lỗi rõ khi thất bại.
  3. Fixture test: startPostgres({ extensions: [] }); tạo bốn vai trò sires_audit_owner, _app, _system (BYPASSRLS), _purge (BYPASSRLS); hai database trong một container: một từ migration, một từ hai file DDL.
  4. Viết apps/audit/src/db/migration.spec.ts: so schema hai database (không cần công cụ ngoài luồng; loại sổ migration của drizzle-orm — EC04), chạy lần hai không đổi (EC01), thiếu vai trò thì dừng (EC02). Ghi cách so ở implement.md.
  5. Khai báo hai file DDL là input của target test trong phần nx của apps/audit/package.json (EC05).

Kiểm

  • pnpm nx run @sires/audit:test → đạt
  • Test: apps/audit/src/db/migration.spec.ts › schema khớp DDL tham chiếu (EC03, EC04); › chạy lần hai không đổi (EC01); › thiếu vai trò thì dừng (EC02)
  • Thao tác tay (EC05): sửa thử một dòng audit.sql, chạy lại lệnh test, thấy đỏ; hoàn tác

Xong khi

  • Migration dựng database khớp DDL tham chiếu; test chạy trong nx affected của CI
