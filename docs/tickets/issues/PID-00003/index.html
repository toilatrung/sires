1. Ticket

  • Mục đích: API nội bộ chỉ nhận JWT ký bằng khóa riêng của từng service (ES256, khóa trong KMS), hạn ≤ 5 phút, và chỉ cho service trong x-callers gọi. Mọi service dùng chung guard này.
  • Gồm: Khóa ký ES256 theo service (kid = tên service), phát và kiểm token; Guard kiểm JWT theo internal/schemas.yaml#/ServiceTokenClaims; Kiểm x-callers, trả 403 caller_not_allowed; Luật actor theo người ký (token agent do orchestration ký, aud mảng; route x-apr chỉ nhận Researcher do gateway ký, kể cả token chuyển tiếp qua orchestration); Client phát token cho lời gọi đi.
  • Không gồm: Khóa KMS của staging và production (PID-00035, PID-00153); Sinh x-callers từ hợp đồng (PID-00007, PID-00008); Bản Python (PID-00005); Chuyển tiếp token khi trả lời prompt (PID-00065); Chọn aud và làm mới token Agent Run (PID-00047, PID-00073).

2. Tiêu chí nghiệm thu

  • PID-00003-AC01 Given token hết hạn hoặc sai chữ ký, When gọi endpoint nội bộ, Then trả 401.
  • PID-00003-AC02 Given service không có trong x-callers, When gọi, Then trả 403 caller_not_allowed.
  • PID-00003-AC03 Given token có sub khác service sở hữu khóa ký, When gọi, Then trả 401 invalid_service_token. (H1)
  • PID-00003-AC04 Given token act.type = agent, When không do orchestration ký hoặc thiếu agentScope, agentRunId, Then trả 401 invalid_service_token; do orchestration ký đủ trường thì qua. (H1; H4)
  • PID-00003-AC05 Given route x-apr, When token không phải act.type = researcher do gateway ký, Then trả 401 invalid_service_token. (H1; H4)
  • PID-00003-AC06 Given client phát token cho lời gọi đi, When service nhận kiểm bằng guard, Then qua với sub = service gọi, aud = service nhận, hạn ≤ 5 phút. (H1)
  • PID-00003-AC07 Given token Researcher do gateway ký có aud = orchestration, When orchestration chuyển tiếp nguyên token tới route x-apr, Then qua; tới route không có x-apr thì trả 401 invalid_service_token. (H2)
  • PID-00003-AC08 Given token act.type = agent do orchestration ký có aud là mảng, When service trong mảng kiểm, Then qua; service ngoài mảng thì trả 401 invalid_service_token; token Agent Run phát ra có hạn ≤ 5 phút. (H3)
  • AC requirement liên quan, phần thuộc luồng này: NFR-AUTHZ-001 (AC01, phần thư viện: agent không qua được route x-apr); NFR-TRANSIT-001 (AC01 không có hành vi kiểm được trong thư viện; kiểm ở PID-00048, PID-00153).

5. Làm rõ

Phiên 11/11/2026 (PO trong phiên)

  • H1: Token nội bộ giữa các service được ký thế nào? → Đ: Mỗi service một cặp khóa ES256, kid = tên service, khóa trong KMS (test: khóa trong bộ nhớ). Service ký lời gọi đi với sub = chính nó; bên nhận kiểm chữ ký bằng khóa công khai theo kid và yêu cầu sub = service ký. Ngoại lệ: token act.type = agent do orchestration phát cho Agent Run (sub = agent-core, bắt buộc agentScope) chỉ nhận khi orchestration ký; act.type = researcher ở endpoint x-apr chỉ nhận khi gateway ký, orchestration chỉ chuyển tiếp nguyên token của gateway trong request trả lời prompt (F-08). Hạn ≤ 5 phút. · Ảnh hưởng: P1–P6, S01–S04, PID-00003-AC03–AC06, EC01–EC10; spec mục 1, 2.3, 4.4, 6
  • H2 (từ I1): Endpoint x-apr nhận token gateway do orchestration chuyển tiếp thế nào? → Đ: A — route có x-apr nhận token act.type = researcher do gateway ký (kid = gateway) có aud là service này hoặc orchestration; orchestration chuyển tiếp nguyên token (F-08); route khác giữ aud chặt. PO trong phiên, 11/11/2026. · Ảnh hưởng: P5, N4, S03, PID-00003-AC07, EC07, EC11; mô tả ServiceTokenClaims (PO sửa cùng nhánh); PID-00065
  • H3 (từ I2): Token Agent Run cho nhiều service và Agent Run dài hơn 5 phút? → Đ: A — token act.type = agent có aud là mảng các service Agent Run được đọc (ServiceTokenClaims.aud là ServiceName hoặc mảng), bên nhận kiểm “aud chứa service này”; hạn vẫn ≤ 5 phút; orchestration trả serviceToken mới trong phản hồi heartbeatAgentRun, agent-core thay token. PO trong phiên, 11/11/2026. · Ảnh hưởng: P2, P5, N5, S01, S03, PID-00003-AC08, EC08; ServiceTokenClaims, AgentRunWorkOrder, heartbeatAgentRun (PO sửa cùng nhánh); PID-00047, PID-00073
  • H4 (từ I3): Token không đạt luật người ký trả mã lỗi nào? → Đ: A — 401 invalid_service_token cho mọi trường hợp không đạt luật người ký (sub khác service ký, token agent không do orchestration ký, route x-apr nhận token không phải Researcher do gateway ký). Token không phải agent có aud mảng cũng bị từ chối với mã này (suy ra từ H3, PO không phản đối). PO trong phiên, 11/11/2026. · Ảnh hưởng: S03, PID-00003-AC04, AC05, AC07, AC08, EC01, EC02, EC08, EC11; mô tả internal/responses.yaml#/InvalidServiceToken (PO sửa cùng nhánh)
