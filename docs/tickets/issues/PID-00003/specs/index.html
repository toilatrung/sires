1. Phạm vi và căn cứ

Mục đíchAPI nội bộ chỉ nhận JWT ký bằng khóa riêng của từng service (ES256, khóa trong KMS), hạn ≤ 5 phút, và chỉ cho service trong x-callers gọi. Mọi service dùng chung guard này.

4.4. Quy tắc và trạng thái

  • Guard kiểm JWT theo internal/schemas.yaml#/ServiceTokenClaims
  • Kiểm x-callers, trả 403 caller_not_allowed
  • Client phát token cho lời gọi đi
  • Mỗi service một cặp khóa ES256, kid = tên service, khóa riêng trong KMS; bên nhận kiểm chữ ký bằng khóa công khai theo kid (H1)
  • Service ký lời gọi đi với sub = chính nó; bên nhận yêu cầu sub = service ký, trừ token Agent Run (H1)
  • Token act.type = agent do orchestration phát cho Agent Run: sub = agent-core, bắt buộc agentScope và agentRunId; chỉ nhận khi orchestration ký (H1)
  • Endpoint x-apr chỉ nhận act.type = researcher do gateway ký; orchestration chỉ chuyển tiếp nguyên token của gateway trong request trả lời prompt, F-08 (H1)
  • Hạn token ≤ 5 phút (ServiceTokenClaims)
  • Mọi trường hợp không đạt luật người ký trả 401 invalid_service_token (H4)
  • Route x-apr nhận token Researcher do gateway ký có aud là service này hoặc orchestration; route khác giữ aud chặt (H2)
  • Token act.type = agent có aud là mảng các service Agent Run được đọc, bên nhận kiểm “aud chứa service này”; orchestration làm mới token qua phản hồi heartbeatAgentRun (H3)
