4.4. Quy tắc và trạng thái

  • 02-roles.sql chạy bằng superuser sires (entrypoint của image chạy file theo thứ tự tên, sau 01-databases.sql). Danh sách 11 service là dữ liệu trong file (một mảng), vòng lặp trong khối DO: chưa có vai trò thì CREATE ROLE; luôn ALTER ROLE đặt lại thuộc tính ở 4.1 và mật khẩu cục bộ (EC03, EC18). Database sires_<svc> có thì: ALTER DATABASE … OWNER TO sires_<svc>_owner; REVOKE CONNECT ON DATABASE … FROM PUBLIC; GRANT CONNECT cho _app, _system, _purge (và vai trò chạy migration theo I1); không có thì bỏ qua phần database của service đó, vẫn tạo vai trò (EC04). Cuối file: nếu có sires_knowledge thì \connect sires_knowledge và CREATE EXTENSION IF NOT EXISTS vector (EC06); không tạo extension ở database khác.
  • Owner phải là chủ database: migration chạy bằng quyền owner cần quyền CREATE trên database (tạo schema app, replica, extension trusted) và quyền trên schema public (PostgreSQL 15+ giao cho chủ database). pgcrypto, unaccent, pg_trgm trusted nên migration tự tạo; vector 0.8.7 không trusted nên init tạo.
  • Volume đã có: entrypoint chỉ chạy /docker-entrypoint-initdb.d khi thư mục dữ liệu trống. local-env.mjs up, sau khi up -d --wait thành công, chạy docker compose exec -T postgres psql -v ON_ERROR_STOP=1 -U sires -d sires -f /docker-entrypoint-initdb.d/02-roles.sql (qua wsl.exe khi ở Windows, như các lệnh khác của file); lỗi → in lý do, mã thoát khác 0 (EC01, EC09, EC10).
  • check-db chạy truy vấn bằng docker compose exec -T postgres psql và kiểm:
    1. vai trò: 44 vai trò (11 × 4) có đúng thuộc tính 4.1 (pg_roles);
    2. chủ database: pg_database.datdba của 11 database là sires_<svc>_owner;
    3. kết nối: vai trò LOGIN của mỗi service có CONNECT ở database của mình, không có ở 10 database còn lại (has_database_privilege), và thử kết nối thật một cặp chéo bị từ chối; superuser sires vẫn kết nối được (EC07, EC08);
    4. đăng nhập bằng mật khẩu: mỗi vai trò LOGIN đăng nhập được database của mình bằng sires-local qua TCP tới địa chỉ không phải loopback của container (pg_hba của image tin loopback, EC16);
    5. extension: sires_knowledge có vector;
    6. chạy lại không đổi: chụp thuộc tính vai trò, thành viên vai trò, chủ và ACL của 11 database, chạy lại 02-roles.sql, chụp lần nữa, so (EC02);
    7. áp DDL tham chiếu (S03, theo I1): với mỗi service, xóa sires_check_<svc> nếu còn (EC12), tạo lại do sires_<svc>_owner làm chủ với quyền CONNECT như database thật (bản tạm của knowledge có vector do superuser tạo), đọc docs/database/ddl/00-common.sql và <svc>.sql ở máy và đưa qua stdin vào psql đăng nhập bằng vai trò chạy migration, kiểm mọi bảng, view, hàm trong app, replica, vec thuộc sires_<svc>_owner, rồi xóa database tạm.
  • Migration không tạo vai trò; script không cấp quyền trên bảng (DDL cấp bằng app.grant_standard, database 11.2).
