1. Ticket

  • Mục đích: PH-02 cần đăng nhập và đăng xuất theo chuẩn OIDC để làm gateway (PID-00038) và kiểm cổng PH-02, nhưng eTroy_OIDC chưa đưa nonce vào ID token và chưa có end_session (SPK-02, K3, K4). Theo D-OIDC, cục bộ và staging PH-02 dùng một OIDC mock thay eTroy thật; nối eTroy thật để lại tới khi eTroy sửa xong. PID này dựng mock đó.
  • Gồm: package @sires/oidc-mock ở infra/local/oidc-mock/ (Node, oidc-provider); authorization code với PKCE S256 bắt buộc; nonce và claim theo scope trong ID token; discovery; JWKS; token với client_secret_basic; userinfo; refresh xoay vòng, dùng lại thì thu hồi family; end_session_endpoint theo RP-Initiated Logout 1.0 (post_logout_redirect_uri đã đăng ký, state); /revoke; client của gateway khai trong file cấu hình; tài khoản thử từ file seed (hai tài khoản A, B, claim như eTroy); chặn chạy ngoài local, staging; log không lộ bí mật; image Docker; service oidc-mock trong compose cục bộ; README (cách gateway trỏ issuer, chạy ở staging, khác biệt với eTroy).
  • Không gồm: mã đăng nhập, đăng xuất của gateway (PID-00038); chạy mock trên staging: image trong registry, Secret, tên riêng sau tunnel (PID-00035); FakeOidcProvider của test (luồng platform); back-channel logout; sửa eTroy_OIDC và nối eTroy thật; production.

Chi tiết phạm vi và edge case: specs/scope.html.

2. Tiêu chí nghiệm thu

  • PID-00160-AC01 Given mock chạy ở local, When đọc discovery và JWKS, Then issuer đúng cấu hình; có đủ endpoint authorize, token, userinfo, JWKS, revocation, end session; PKCE chỉ S256; ID token ký RS256; JWKS có một khóa RSA có kid.
  • PID-00160-AC02 Given client của gateway và tài khoản A, When một RP chuẩn đăng nhập bằng authorization code với state, nonce, PKCE S256 và đổi code bằng client_secret_basic, Then ID token có iss, aud, sub của A, nonce đã gửi, hạn 900 giây, name, email, email_verified; có refresh token; /userinfo trả cùng claim.
  • PID-00160-AC03 Given như AC02, Then thiếu PKCE, PKCE plain, redirect_uri chưa đăng ký, sai mật khẩu, sai code_verifier, code dùng lại, sai client_secret đều bị từ chối và không cấp token.
  • PID-00160-AC04 Given refresh token R1, When refresh, Then nhận token mới và R2; dùng lại R1 thì invalid_grant và R2 cũng hết dùng được.
  • PID-00160-AC05 Given A đã đăng nhập, When mở end_session_endpoint với client_id (như gateway gửi) hoặc id_token_hint, post_logout_redirect_uri đã đăng ký (/sign-in) và state nếu có, Then phiên mock kết thúc và trình duyệt về URI đó (kèm state khi có); URI chưa đăng ký thì không chuyển hướng tới đó.
  • PID-00160-AC06 Given refresh token còn hạn, When POST /revoke với client_secret_basic, Then refresh bằng token đó bị invalid_grant.
  • PID-00160-AC07 Given file seed của repo, Then có hai tài khoản A, B khác sub và email; mỗi tài khoản đăng nhập được với claim của mình; sub không đổi qua các lần đăng nhập.
  • PID-00160-AC08 Given OIDC_MOCK_ENV thiếu hay khác local, staging (kể cả production), hoặc staging mà issuer không https, thiếu cookie key, dùng mật khẩu hay secret cục bộ, chỗ giữ chỗ của file mẫu, When khởi động, Then thoát mã 1 trước khi mở cổng.
  • PID-00160-AC09 Given máy Dev, When pnpm local:up --build, Then oidc-mock healthy và discovery đọc được ở http://localhost:9400; image không chứa .sires/, .env*, .git.
  • PID-00160-AC10 Given log của mock trong một luồng đăng nhập, refresh, đăng xuất, thu hồi, Then không có token, code, mật khẩu, secret, cookie.
  • AC requirement: không có riêng. PID tạo môi trường để PID-00038 và PID-00055 kiểm INT-OIDC-001–004 ở cổng PH-02.

Bảng AC → test → slice: specs/acceptance.html.
