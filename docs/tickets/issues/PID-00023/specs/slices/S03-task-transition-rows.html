Một lát dọc làm xong và kiểm được độc lập, trong đúng luồng của ticket. Trạng thái thực hiện ghi ở report.md của Dev, không ghi ở đây.

Phụ thuộcS01, S02; PID-00158 (hàm sinh SQL nạp dòng, hàm so dòng — H2; chưa làm, ghi nhận không chặn Sẵn sàng).

Làm

  1. Sinh SQL nạp dòng app.state_transition cho machine task (gồm cột code = T-NN) từ khai báo của S02 bằng helper của PID-00158 (hàm sinh SQL hoặc lệnh in SQL của PID đó, đọc danh sách machine mà module domain xuất) và đặt vào một custom migration SQL mới của drizzle-kit, sau migration đầu của S01 (H1, H2); không chép tay, không sửa tay file sinh ra. Cách gọi (script trong package.json hay lệnh khác) Dev chọn, ghi README và implement.md.
  2. Viết apps/planning/src/db/state-transition.spec.ts (tạo mới): sau migration, dòng task trong bảng bằng khai báo (dùng hàm so dòng của PID-00158) và bằng dòng của database dựng từ DDL tham chiếu (EC11).
  3. Test trigger: với mỗi cặp trong 100 cặp, tạo Task ở trạng thái nguồn (chèn bằng vai trò có quyền, kèm task_definition và replica.project_state Active cần cho ràng buộc), UPDATE status sang đích bằng _app: 28 cặp qua, 72 cặp bị task_state từ chối; UPDATE giữ nguyên status không lỗi (EC06).

Kiểm

  • pnpm nx run @sires/planning:test → đạt
  • Test: apps/planning/src/db/state-transition.spec.ts › bảng khớp khai báo và DDL (EC11); › trigger task mọi cặp (DATA-STATE-001-AC01, NFR-MAINT-003-AC01); › cùng trạng thái (EC06)
