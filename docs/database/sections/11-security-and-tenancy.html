11.1. Row-Level Security

Lớp thứ hai của cách ly (lớp thứ nhất là repository có TenantContext, kiến trúc 6.3). app.enable_tenant_rls() chạy cuối mỗi file DDL, bật cho mọi bảng có cột account_id trong app, replica, vec:

ALTER TABLE app.<t> ENABLE ROW LEVEL SECURITY;
ALTER TABLE app.<t> FORCE ROW LEVEL SECURITY;          -- áp cả với owner
CREATE POLICY tenant_isolation ON app.<t>
  USING (account_id = app.current_account_id())
  WITH CHECK (account_id = app.current_account_id());  -- không ghi được dòng cho tài khoản khác
  • app.current_account_id() đọc SET LOCAL app.account_id; thiếu biến → NULL → 0 dòng (an toàn mặc định).
  • Không bật RLS: outbox, inbox, job_lock, state_transition (vai trò _app không đọc được ba bảng đầu; bảng cuối là dữ liệu tham chiếu), embedding_model_catalog (toàn hệ thống).
  • Truy cập trước khi có tenant context (đăng nhập, tra phiên): hàm SECURITY DEFINER trả tối thiểu cột — app.find_account_by_identity, app.find_session; search_path cố định.
  • View dùng security_invoker = true để RLS của bảng gốc áp dụng (analysis_same_model, research_project_live).
  • Cách ly project trong cùng tài khoản (CTX-ISOLATION-001) ở lớp ứng dụng và Context Assembler; truy vấn vector luôn lọc theo phạm vi project (7.5).

11.4. Kiểm thử cách ly

Bổ sung cho bộ test 19.12 (endpoint đọc với id của tài khoản khác → 404):

  • Mỗi database: đăng nhập bằng _app, đặt app.account_id của tài khoản B, đếm mọi bảng có account_id chứa dữ liệu của A → 0 dòng; bỏ app.account_id → 0 dòng.
  • INSERT/UPDATE dòng mang account_id của tài khoản khác → lỗi policy.
  • Kiểm tự động mọi bảng mới đều có RLS: truy vấn pg_class.relrowsecurity cho mọi bảng có cột account_id trong CI.
  • Kết quả chạy thử trên DDL tham chiếu: 12.4.
